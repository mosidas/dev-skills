# スキル群自体を構成するドキュメントのレビュー観点カタログ

スキル群自体を構成するドキュメント(スキル群自体の品質 = メタレベル。`./principles.md` §1)を対象とする、種別別のレビュー観点。`meta-review` が使う正本。成果物の品質向けの `../../dev-core/references/review-perspectives.md` に対応する、スキル群自体の品質側の観点定義である。

これらのドキュメントは多くが **LLM エージェントが読んで実行する指示**である点が特徴で、「人間が読めるか」だけでなく「LLM が誤解なく実行できるか」を品質とする。

## 1. 種別の識別

対象ファイルをまず種別に判定する。

| 種別 | 該当 | 読み手 | 性質 |
| ---- | ---- | ------ | ---- |
| ① 実行手順書(SKILL) | `*/SKILL.md`(dev-* / flow-* / ext-*) | LLM エージェント | 手順・契約の定義 |
| ② 正本リファレンス | `dev-core/references/*`、`meta-core/references/*` | LLM + 人間 | 複数箇所が参照する SSoT |
| ③ 成果物テンプレート | `templates/*-template.md`、`templates/ssot/*` | 生成する LLM | 生成物の構造契約 |
| ④ プロンプト雛形 | `templates/*-prompt.md` | サブエージェント LLM | 委譲の指示 + 返却契約 |
| ⑤ エージェント定義 | `agents/*.md` | LLM(起動時) | frontmatter + システムプロンプト |
| ⑥ スクリプト | `scripts/*.py` | 実行環境 | 決定論的処理 |
| ⑦ 設計正本 | `.meta/DESIGN.md`(構造・現状)、`.meta/decisions/`(判断・履歴) | 人間 | アーキテクチャの俯瞰・根拠 |
| ⑧ 利用者向け説明 | `README.md` 各種、`workflow.json` | 人間 / エンジン | 導入・状態機械定義 |

## 2. 種別別観点

### ① 実行手順書(SKILL)

「LLM が誤解なく実行できるか」を品質とする。

- **実行可能性**: 各ステップが具体的な操作・判断基準を持つ。曖昧な動詞(「精緻化」「適切に」等)がない。分岐条件が明示されている。
- **契約の完全性**: 入力・出力・workdir・port が冒頭で定義され、他部品との境界が明確。
- **停止と承認の境界**: どこで自走し、どこで止まって誰が承認するかが明示されている。
- **再開可能性**: 中断後にファイルから現在地を復元できる手順である。
- **責務の単一性**: 「やらないこと」が明示され、他部品へ越境していない。
- **安全制約**: 破壊的 git 操作の禁止・間接プロンプトインジェクション耐性のエコーがある。

### ② 正本リファレンス

「SSoT が本当に単一か」を品質とする。ドリフトの最大の源。

- **単一正本性**: 同じ規範が複数箇所に実体で書かれ、ドリフトしていない。「正本はここ、他はエコー」の宣言がある。
- **非重複**: reference 間で責務が重複していない。
- **根拠の明示**: 規範に出典(URL・原典)が添えてある。
- **適用可能性**: 抽象論でなく、部品が実際に従える具体性がある。

### ③ 成果物テンプレート

「機械検査と生成物が噛み合うか」を品質とする。

- **パーサ整合**: `check.py` / `lib.py` が期待する構造(`### Requirement N:`、`N.M`、`_Requirements:` 等)と一致する。
- **記法規約準拠**: `../../dev-core/references/notation.md` の ID・マーカー・注記に従う。
- **記入例の自己無矛盾**: プレースホルダ例自身が規約を満たしている。

### ④ プロンプト雛形

「返却が構造化され抽出可能か」を品質とする。

- **返却契約の厳密さ**: STATUS / VERDICT 等の enum・必須項目が定義され、本文の曖昧表現に依存しない。
- **スコープ限定**: 1 サブエージェントに 1 責務だけを渡す設計である。
- **参照自己完結**: 仕様本文を転記せず参照先を読ませる方針が一貫している。
- **安全則のエコー**: インジェクション耐性等が含まれ、正本と整合する。

### ⑤ エージェント定義

- **frontmatter 妥当性**: `name` / `description` / `model` が揃い、`description` が起動判断に足る。
- **正本との非重複**: システムプロンプトが正本(`orchestration-patterns.md` 等)のエコーに留まり、重複定義していない。
- **役割の単一性**。

### ⑥ スクリプト

- **文書との整合**: 検査項目が `notation.md` / `static-check.md` の記述と一致する。
- **決定論性**: 機械判定できることだけを扱い、意味判断を混ぜていない。
- **テストの有無**。

### ⑦ 設計正本

- **現状との一致**: `DESIGN.md` が `.claude` の現状と乖離していない(乖離は `meta-doc` の全上書き再生成で解消する。D-004)。
- **層の分離遵守**: 判断・履歴の記述が `decisions/` にあり、現状生成物の `DESIGN.md` に混ざっていない(`./principles.md` §3・D-004)。
- **判断の追跡可能性**: `decisions/` の各エントリが必須節をすべて持ち、索引(`decisions/README.md`)から到達できる。必須節の正本は `decisions/README.md`。

### ⑧ README

- **導入手順の再現性**: 記載どおりに実行して動く。
- **最新性**: 現行の構成・命名と一致する。

## 3. 横断観点(全種別に適用)

種別別より効く。SSoT 分散 + ファイル契約という設計上、局所的に正しくても全体で不整合が起きるのが最大の失敗モードである。

- **クロスドキュメント整合**: 状態名・ゲート名・部品名・ファイル名・ID 体系が全文書で一致する。多くは `grep` で機械化でき、`meta-check` の担当とする。
- **参照の実在**: SKILL・reference・template 間の相対パス、`[[リンク]]`、inject 先スキル名が実在する。リンクチェッカで機械化でき、`meta-check` の担当とする。
- **言語・記述規約**: 日本語、曖昧動詞の排除、前置き・過度な装飾の排除、根拠の明示(プロジェクトの `CLAUDE.md`)。

## 4. 適用

- `meta-review` は対象ファイルの種別(1.)を判定し、該当する**種別別観点(2.)+ 横断観点(3.)**で検査する。
- 観点ごとに 1 レビュアーへ分割する分業は、生成物レビューの文書ゲート(`../../dev-core/templates/doc-gate-prompt.md`)に準じる。
- 機械で判定できる横断観点(整合・参照実在)は `meta-check` に委ね、`meta-review` は意味判断に集中する(決定論と意味判断の分離)。
