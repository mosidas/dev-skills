# リサーチメモ・ディスカッションペーパー・企画書の型

## 1. この型が答える問い

リサーチメモが答える問いは「この論点について、今どこまで分かっていて、何がまだ決まっていないか」であり、その先に「読んだ人に何を判断してほしいか」がある。記録(議事録)でも確定情報の伝達(レポート)でもなく、結論が固まる前に、たたき台として読者の判断や議論を引き出すために書く。中心主張と未解決の論点を、どちらも隠さず両方書く。

## 2. 必須要素

- タイトルまたは冒頭一文の中心主張(「〜について」でなく「〜すべきである」「〜が課題である」の形)。
- スコープと対象外。あえて論じない理由(他の場で決着済み、今回は情報不足)を一言添えると、抜け漏れでなく意図的な線引きだと伝わる。
- 背景 → 問題設定 → 提案・論点 → 未解決の論点 → 結論の流れ。
- このメモで何を決めたいか(たたき台としてのゴール)の冒頭での明示。

## 3. 構成の型

- 冒頭で中心主張とゴールを渡してから、背景・問題設定に移る。結論が未確定なら「暫定的な結論」「現時点での見立て」と明示したうえで、やはり先に渡す。背景から順に読まないと主張にたどり着けない構成にしない。
- 概念の定義は用語集に切り出さず、地の文に溶け込ませる。「Xとは〜である」の定義文が段落の先頭に 3 回続くと機械的な鋳型に見えるため、括弧の同格挿入(「起動率(アプリを開いてから〜まで進んだ利用者の割合)は」)や、使ったあとで名づける形(「この動線を、本メモでは便宜的に『平時導線』と呼ぶ」)を混ぜる。
- 比較・選択肢は、メリット・デメリットの羅列でなく、軸を定めた比較表にする。共通の軸(「到達速度」「コスト」)で並べると、読者は自分の優先順位で表を読み替えられる。
- 読者に賛成・反対の反応を求める前提で書く。「この軸で判断するなら、どちらに傾くか」を論点の直後に置くと、読者は応答する読み方に切り替わる。

## 4. 品質基準

- タイトルか冒頭一文だけで、このメモが何を主張しているか伝わる。
- 未解決の論点が、著者の暫定スタンスつきで書かれている。「分からない」で止めず、「分からないが、今のところこちらに傾いている」まで書く。列挙して「今後の検討課題」で締めない。
- 比較・選択肢の提示に、読者が使える判断軸がある。
- 著者自身が触れた事例・数値が中心主張を支えている。固有名詞・数値抜きで成立する主張は素材不足の疑い(`paragraph.md` 4.)。
- 読んだ人が、次に何を判断すればいいか分かる。

## 5. やりがちな失敗

- 概念モデルだけを組み立て、著者の一次情報・実体験がまったく出てこない(「一般に〜と考えられる」だけの段落)。触れた論点 2〜3 個に絞って濃く書き、残りは正直に薄く書く。
- 未解決の疑問を羅列して終わり、著者の見解がどこにもない。メモが疑問集で終わり、議論の起点にならない。
- 固まっていない論点を確定事項のように断定し、後で訂正が要る。

## 6. 共通規範への例外と重み付け

- 例外: なし。共通規範をそのまま適用する。
- 重み付け: 結論先行(`composition.md` 5.1)、確信度の明示と暫定スタンス(`sentence.md` 6.)、因果は地の文・箇条書きは真の並列のみ(`paragraph.md` 1.)。暫定スタンスは論点への見立てであって、論点への優先順位・段階の付与ではない(`composition.md` 4.6 の「濃淡は強弱であって順序づけではない」)。

## 7. 冒頭の例

- Before: 「# 地域防災アプリの検討について」+ 論点の箇条書き + 「今後さらなる検討が必要である。」
- After: 「# 防災アプリは「平時に使われない設計」が最大の失敗要因になる」+ 中心主張と判断してほしい論点 3 つの提示 + 「未解決なのは高齢者向けUIの検証方法で〜外部の使い勝手調査に予算をつけるかどうかをこのメモの結論としたい。」
