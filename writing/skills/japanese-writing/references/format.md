# 表記・書式の規範(L1)

## 1. 記述フォーマット

- Markdown 形式で記述する。GitHub での表示を前提とし、[GitHub Flavored Markdown](https://github.github.com/gfm/) に従う。

## 2. 文書構成

- 見出しは、レベル 2〜5 に付番する。レベル 1(タイトル)とレベル 6 以上には付番しない。
  - レベル 2: `1.`、`2.`、…
  - レベル 3: `1.1.`、`1.2.`、…
  - レベル 4: `1.1.1.`、…
  - レベル 5: `1.1.1.1.`、…
- ある見出しに本文があり、その下にさらに細分化した見出しがある構成にしてはならない。本文は最下位の見出しの下にのみ置く。
- 見出しは内容を特定できる具体的な句にする。その節が答える問い、または扱う対象を指す。手順だけを述べる見出しや、節の結論を言い切る「セリフ」にしない。
- 前項の規定はレベル 2 以下の見出しに適用する。レベル 1(タイトル)の扱いは文書タイプの規定に従う(`doctypes/*.md`)。

## 3. 表記

- 英数字は半角を使用する。
- 文体は常体で統一することを推奨する。
- 能動態を優先する。
- 体言止めを避ける。
- 略語は、初出時に正式名称を併記する(例: `GitHub Flavored Markdown(GFM)`)。
- 外来語(カタカナ)の表記は[外来語表記ガイドライン](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/kokugo_kadai/iinkai_45/pdf/93390601_09.pdf)、漢字・送り仮名は[公用文における漢字使用等について](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/sanko/koyobun/pdf/kunrei.pdf)、物理量の単位は[国際単位系](https://japanknowledge.com/contents/common/si.html)に従う。
- 規約の要請レベルを規定する場合、[RFC2119](https://www.nic.ad.jp/ja/tech/ipa/RFC2119JA.html) に対応する語句を使用し、その対応をドキュメントの最初で明示する。

| 要請レベル | 語句                                   | 説明                                                 |
| :--------- | :------------------------------------- | :--------------------------------------------------- |
| MUST       | しなければならない、する               | 絶対に守る必要がある。                               |
| MUST NOT   | してはならない、しない                 | 絶対に禁止される。                                   |
| SHOULD     | する必要がある、推奨される、が望ましい | 原則として従うべきだが、理由があれば例外も許容する。 |
| SHOULD NOT | しないほうがよい、推奨されない、避ける | 原則として避けるべきだが、理由があれば使用を許容する。 |
| MAY        | してもよい、できる                     | 任意で使用してよい。個人の裁量に任せる。             |

- 必要に応じて[アラート記法](https://docs.github.com/ja/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#alerts)を使用してよい。

## 4. 記号

- 区切り符号は、句点「。」、読点「、」、中点「・」、コロン「:」を使用する。
  - 句点は、文の終わりに使用する。ただし、箇条書き・例の表記で名詞句のみを記述する場合は使用しない。
  - 読点は、語句の切れ・続きを明らかにするために使用してよい。
  - 中点は、名詞を並列する場合で、読点では読みにくいときに、名詞の連結に使用する。
  - コロンは、用語・記号を説明する場合に、その後ろに付けて使用する。
- 分かち書きには半角スペース「 」を使用する。
- 引用符号は鉤括弧「」、範囲を表すときは波ダッシュ「〜」、省略は三点リーダー「…」、小数点はピリオド「.」、桁区切りはカンマ「,」を使用してよい。
- 括弧は、半角の `()`、`[]`、`{}` を使用する。
- 数式・コード・固有名詞を除き、上記以外の記号は使用しない。
- 全角スペースは使用してはならない。

## 5. 図・表・式・コード

- 図は mermaid 記法または画像で表現する。表は Markdown 記法または画像で表現する。数式はインラインを `$`、ブロックを `$$` で記述し、[数式の記述方法](https://docs.github.com/ja/get-started/writing-on-github/working-with-advanced-formatting/writing-mathematical-expressions)に従う。
- 図・表・式には必要に応じて番号を付ける(「図 1: …」「表 1: …」「(1)」)。
- 図の内容(何を図にするか、要素と関係の描き方)は diagram-authoring の規範に従う。
- 「用語: 説明」の対応が 3 項目以上並ぶときは、箇条書きでなく表にする。列名(場面・操作、構成要素・役割 など)を置くことで、各項目が何の軸で並んでいるかが読者に伝わる。
- コードはインラインを `` ` ``、ブロックを ` ``` ` で示す。例示するコードには、要請レベルに応じた説明コメントを付ける。
  - `// 🔆Best`: 複数の Good な例示の中で Best なとき(MUST, SHOULD, MAY)
  - `// ✅Good`: Good な例示(MUST, SHOULD, MAY)
  - `// 🤔Not Recommended`: 推奨されない例示(SHOULD NOT)
  - `// 😡Bad`: 悪い例示(MUST NOT)

## 6. 参照・引用

- 文中参照は、図・表・式・章節番号で行う(例: 「表 2 に示す」「10.2 を参照」)。
- 外部リンクはアンカーテキストで表記し、URL の直接表記は避ける。
- 参考文献が必要な場合は末尾に列挙し、文中から番号で参照してよい。

## 7. 表記の一貫性

- 同一語の表記ゆれ(「ユーザー/ユーザ」「行う/行なう」)を同一文書内に混在させない。同じ対象が異なる表記で現れると、読者は「別のものを指しているのか」と立ち止まる。長い文書では用語集を作って運用する。
- 同じ対象を指す別語(「検証手段」と「検証方式」、「ハーネス」と「agent harness」)も 1 つに決めて通す。表記ゆれと同じ負荷を読者に掛ける。
- 表・図・コードで使った語は、地の文でも同じ語で受ける。表の列見出しが「方法」なら本文も「方法」と書き、「守り方」のような別の言い方に置き換えない。読者は表と本文を往復しながら読むため、対応が取れないと同じ対象と判断できない。
- 英語名の併記は初出の括弧だけにする(略語の正式名称併記は 3. に従う)。2 回目以降は日本語だけで書く。
- 「日本語(英語)」の併記では、括弧の内外が同じ対象を指すことを原典で確かめる。原文の語句を切り出すと、指す範囲がずれることがある(「注意(attention budget)」では、英語側が注意の総量を指し、日本語側と対応しない)。
- 句読点のスタイル(「、。」と「，．」)を混在させない(使用する記号は 4. に従う)。
- 数字の全角・半角を混在させない(英数字の半角は 3. に従う)。
- 意味の切れ目と一致しない位置での改行や、禁則処理違反(行頭の句読点・閉じ括弧)を避ける。
