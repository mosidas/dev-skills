# プロジェクト原則

本文書はプロジェクト原則を定める知識 port である。dev-implement が実装時に常時注入し、dev-spec・dev-check 等の inject 先も参照する。
常時注入されるたびにコンテキストを消費するため、簡潔に保つ。プロジェクトに関係しない項目は削る。
各原則は「原則文 + なぜ必要か(根拠)を 1 行」の形で書く。

## 1. プロジェクト固有原則

### 1.1. テスト方針

- <原則文: テストの範囲・粒度・モックの扱いなどを 1 文で>
  - 根拠: <なぜ必要か。守る品質・防ぐ事故を 1 行で>

記入例:

- モックはシステム境界(外部 API・DB・ファイルシステム)のみに使い、内部コンポーネント間はモックしない
  - 根拠: 内部モックは実装構造に結合し、リファクタリングで壊れる偽陽性テストを生むため
- 分岐を持つロジックは両分岐をテストする(if/else は両側、null は存在・不存在の両方)
  - 根拠: 片側だけの合格は分岐の半分を無検証のまま通すため

### 1.2. 設計方針

- <原則文: レイヤ構成・依存方向・エラーハンドリングなどを 1 文で>
  - 根拠: <なぜ必要か>

記入例:

- レイヤ構成を事前に固定し(例: プレゼンテーション → アプリケーション → データアクセスの 3 層)、依存は単方向に保つ
  - 根拠: 実装中の場当たり的な構成変更は、ビジネスロジックの散在と循環依存を生むため
- 例外は共通基底クラスを継承し、業務例外(既知)とシステム例外(未知)を区別する
  - 根拠: 区別がないと集約ハンドラがログレベル・ユーザー向け文言を出し分けられないため

### 1.3. コーディング規約

- <原則文: 型・命名・禁止事項などを 1 文で>
  - 根拠: <なぜ必要か>

記入例:

- 型 `any` を禁止する(やむを得ない場合は理由コメントを併記する)
  - 根拠: `any` は型検査を局所的に無効化し、静的検査ゲートの検出力を落とすため
- 環境で変わる値(接続先 URL・機能フラグ等)はハードコードせず、設定(環境変数)経由で解決する
  - 根拠: ハードコードされた設定はテストで検出できず、実環境で初めて露見するため

### 1.4. 品質ゲート

- <原則文: CI で合格必須とする検査と閾値を 1 文で>
  - 根拠: <なぜ必要か>

記入例:

- formatter・linter・型チェッカの三層を設定ファイルで定義し、CI で合格必須とする。抑制コメントには対象ルール名と理由を併記する
  - 根拠: 人手レビューだけでは規約逸脱の検出が安定しないため
- テストカバレッジの下限値(行・分岐)を定め、下回りを不合格とする
  - 根拠: 下限がないとテスト追加がタスクの都合で後回しになり、劣化に気づけないため

## 2. 標準準拠の原則

外部標準・確立された一般則を非交渉的な原則として採用したもの。プロジェクトの規模・分類・特性に照らして必要な標準だけを、本表の形式(原則文 + 根拠となる標準名・版)で選んで書く(注入のたびにコンテキストを消費するため、関係しない標準は載せない)。採用を検討して見送った標準は 3. に理由付きで記録する。
プロジェクトで別の標準(社内規約・業界規制等)を採用する場合は、同じ形式(原則文 + 根拠となる標準名・版)で行を追加する。

| ID    | 適用条件 | 原則                                                                                 | 根拠(標準・版)                        |
| ----- | -------- | ------------------------------------------------------------------------------------ | ------------------------------------- |
| SEC-1 | 常に     | 設計・実装で CWE Top 25 および OWASP Top 10 のカテゴリに該当する脆弱性を作り込まない | CWE Top 25 (2024) / OWASP Top 10:2025 |

## 3. 対象外の記録

採用しなかった原則ドメインを「対象外 + 理由」で 1 行ずつ残す。JBGE(Just Barely Good Enough: 文書はいま必要な分だけに保つ)の考え方に基づき、原則の本文は残さず判断の痕跡だけを 1 行で残す。

- 対象外: <ドメイン名(標準名)> / 理由: <該当しない事実を 1 行で>

記入例:

- 対象外: モバイルセキュリティ(OWASP Mobile Top 10) / 理由: モバイルクライアントを提供しないため
- 対象外: アクセシビリティ実装(WCAG 2.2) / 理由: GUI を持たない CLI ツールのため
- 対象外: LLM セキュリティ(OWASP Top 10 for LLM Apps) / 理由: 生成 AI 機能を持たないため
