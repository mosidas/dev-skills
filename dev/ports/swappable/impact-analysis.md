## 2. 使いどころ

| 部品          | 使う場面                                                     |
| ------------- | -------------------------------------------------------------- |
| dev-check     | 検査対象の絞り込み(Step 2 の調査の隔離に渡す候補の決定)      |
| dev-decompose | File Structure Plan を立てる際の既存構造の把握(Step 2)       |
| dev-implement | レビューで `git diff` と照合する範囲の決定、テスト欠落の候補   |

## 3. 限界(必ず守る)

- 算出結果は**補助**であって、**範囲外を見なくてよい根拠にはならない**。過剰検出(無関係な箇所の列挙)も見落としも起こる。
- 使う方向は部品ごとに異なる。dev-check・dev-decompose では読む範囲を絞る候補として使ってよい(絞ったときは範囲外を報告する)。dev-implement のレビューでは範囲を**広げる**用途に限り、範囲を狭める根拠にしない。
- 算出結果を根拠に検査・レビューの範囲を狭めたときは、検査した範囲と方法、範囲外として扱った箇所を報告に明示する(「検出できなかったことを問題なしと断定しない」規律を維持する)。
- 手段が失敗した・インデックスが古い場合は、既定の手順(読んで判断する)へ戻す。結果が空であることを「影響なし」と読まない。
