# ヒアリング質問セット(hearing-questions)

dev-spec が仕様化の質問駆動(SKILL.md Step 2)で使う質問セットを、この port で差し替える(dev-spec が `name: hearing-questions` を参照する。契約は dev-spec の SKILL.md「契約」節)。dev-spec の既定質問に対し、プロジェクト・組織に固有の確認事項を定める。依頼文から確定できる項目は質問しない(推測禁止の原則は維持する)。

## 1. 必ず確認する(推測で埋めない)

- 利用者とロール: 想定利用者・権限区分(例: 管理者 / 一般 / ゲスト)
- 準拠レベル: セキュリティ・規制・社内標準のうち本作業に効くもの
- 技術スタック・インフラ制約: 言語・フレームワーク・実行環境・既存資産との整合
- ドメインルール: 業務固有の制約(例: 締め処理・与信・在庫の規則)
- 機能境界: 含む機能 / 含まない機能の線引き
- 非機能要件: 性能・可用性・監査ログ等の有無と目標値

## 2. 条件付きで確認する

- 認証を含む場合: 認証方式・初期ユーザーの供給・セッション永続戦略・失効時の挙動(`auth-session` 知識 port と整合させる)
- GUI を含む場合: 視覚設計の正本(デザイントークン・共通レイアウト)の有無(`frontend-design` 知識 port と整合させる)
- 置換・移行を含む場合: 削除対象・使用ゼロ確認・後方互換の要否(`migration` 知識 port と整合させる)

## 3. 記録

- 確定した回答は spec.md の目的・スコープ・前提へ反映する。未確定は `[要確認: ...]` を残し、推測で埋めない。
