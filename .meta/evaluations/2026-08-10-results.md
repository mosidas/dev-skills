## E-004: 破壊的な git 操作と一括ステージングの拒否

導入先の `.claude/skills/ext-dev-guardrails/hooks/guard_bash.py` へ PreToolUse の JSON を渡した。

| 入力 | exit | 出力 |
| ---- | ---: | ---- |
| `git reset --hard HEAD~1` | 2 | 「`git reset --hard` は未コミットの変更を失う」+ 代替手段 |
| `git add -A` | 2 | 「一括ステージングは無関係な変更を巻き込む」+ 代替手段 |
| `git -C . reset --hard` | 2 | 同上(グローバルオプションで回避されない) |
| `FOO=1 git clean -fd` | 2 | 「`git clean -f` は追跡外のファイルを失う」(環境変数の前置で回避されない) |
| `git push origin +main` | 2 | 「`+` を前置した refspec は強制 push であり、共有された履歴を書き換える」 |
| `git add src/main.py` | 0 | なし |
| `git revert HEAD` | 0 | なし |
| `git stash push -m wip` | 0 | なし |
| `git commit -m "wip; git reset --hard は禁止"` | 0 | なし(クォート内の区切りで分割しない) |
| `git push --force-with-lease origin feature` | 0 | なし |

拒否の出力には、代替手段(コミット済みは `git revert`、未コミットは `git stash push`、ステージングは `git add <file>`)と正本の所在が含まれた。期待挙動と一致した。

```

```

hook は書き込みを拒否し、`check.py` は書き込みの後に検出する。D-018 が述べる「検出と防止の差」が両方の実行で確かめられた。期待挙動と一致した。
