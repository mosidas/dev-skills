# D-005: 品質の対象の呼称を「レイヤー A/B」から「成果物の品質 / スキル群自体の品質」へ改める(2026-07-14)

## 背景

品質を担保する対象を D-001 以降「レイヤー A(生成物)/ レイヤー B(スキル群自体)」と呼んでいた。しかしこの「レイヤー」は依存の同心構造(層 0/1/2)とは別の概念で、A/B が層 0/1/2 のいずれか一つを指すかのように読め、誤解を招いた。層 0/1/2 は OSI 参照モデルの各層(物理層等)にあたる構造で、A/B はむしろ「OSI モデルそのもの」に相当する上位の区別(品質を適用する対象)である。A と B の関係も「レイヤー」という語では表せていなかった。

## 決定

- 品質の対象を、層と混同する「レイヤー A/B」ではなく、対象そのもので呼ぶ。
  - **成果物の品質**(旧レイヤー A): スキル群が生成する成果物(spec.md・コード等)。dev 分類が担保(check.py・文書ゲート・観点レビュー)。
  - **スキル群自体の品質**(旧レイヤー B): スキル群自体を構成するドキュメント(`.claude`・`.meta` 等)。meta 分類(`meta-*`)が担保。
- 両者の関係を **対象レベル / メタレベル(自己適用)**と明記する。スキル群自体の品質は成果物の品質のメタレベルで、同じ品質哲学(コードが SSoT・承認ゲート・決定論的検査・観点レビュー)を、適用対象を「生成物」から「スキル群自体」へ向け直したもの。`meta-*` は 1 段上位からスキル群全体を入力データとして検査・生成する(一方向: `meta-*` → 対象)。
- 「品質を担保する対象(A/B)」と「機構の系統(分類 dev/meta)」は別軸だが、スキル群自体の品質を担う機構が meta 分類なので密接に対応する。

## 却下した選択肢

- **短縮ラベル(対象品質/メタ品質)や「品質ドメイン A/B」を残す**: A/B の記号が対等な 2 つに見える難点が残る。対象そのもので呼ぶ方が誤解が少ない。

## 帰結

- LIVE ドキュメント(principles.md・doc-perspectives.md・meta-check/meta-review/meta-doc の SKILL・meta_check.py・DESIGN.md・design-template.md)の「レイヤー A/B」表記を新呼称へ更新した。principles.md §1 の見出しを「2 つの品質の対象(対象レベルとメタレベル)」にし、関係を明記した。
- 過去の判断記録 D-001・D-004 は追記規約(decisions は追記のみ)に従い原文のまま残す。両者の「レイヤー B」は本改称後の「スキル群自体の品質」にあたる。
- 「分類 dev/meta」「層 0/1/2」の呼称は変更しない(本改称は品質の対象の呼称のみ)。

## 再検討条件

「スキル群自体の品質」等の対象名が長く運用上不便と判明した場合(その場合も「レイヤー」を含む呼称は避ける)。
