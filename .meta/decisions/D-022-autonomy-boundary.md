# D-022: 自走と headless をレイヤー 3 に閉じ、dev-author をコアから外す(2026-08-10)

## 背景

`flow-sdd` は承認ゲート(ルーティング・roadmap・spec・tasks)をすべて人間承認とし、自走は「部品を直接束ねる拡張ワークフロー(レイヤー 3)」に委ねると述べる。その拡張は存在せず、反復実行の設計(反復上限・巻き戻し・headless での扱い)は決めていなかった。

削除前の `dev/agents/dev-author.md` は「composition が自走ループでサブ部品の成果物生成を隔離委譲するときにのみ起動される」と定める。リポジトリ全体を検索したところ、`dev-author` を起動する記述は無く、言及は `orchestration-patterns.md` 5.(役割の説明)・`../DESIGN.md`・`D-000` 8.1 の 3 箇所だけである(`../notes/2026-08-10-engineering-lenses.md` L-7)。`install.py core` は `<グループ>/agents/*.md` をすべて配布するため、利用側では起動経路を持たないエージェント定義が 1 件常駐し、description の読み込み量だけを払う。

`claude -p` による headless 実行は、`AskUserQuestion` と明示承認に依存する flow-sdd では承認待ちで停止する。Stop hook による自走も、承認ゲートでの正しい停止をブロック対象と区別できない。

## 決定

- **コアの部品・composition は自走しない**。headless 実行(`claude -p`)と Stop hook をコアの対象外とする。反復上限・コスト監視(`--output-format json` の `total_cost_usd`)・権限の限定(`--allowedTools`)は、自走するレイヤー 3 の拡張が定める。この境界を `flow-sdd/SKILL.md` 7.(対応しないこと)に明記する。
- **コアに全体の反復上限を追加しない**。現在の有界リトライ(レビュー却下の再投入 2 回・デバッガ 2 ラウンド・検証失敗の修復 3 ラウンド・CI 修正 3 ラウンド)は維持する。承認ゲートの停止点が全体の上限として働くため、承認を持つ構成では追加の上限が要らない。
- **`dev-author` をコアから外す**。自走ループを実装する拡張バンドルが `<バンドル名>-author` として同梱する(`../../dev/extensions/README.md` 3.1 の同梱エージェント規約に従う)。
- **D-000 8.1 の役割エージェント 5 体構成を 4 体へ改める**(supersede)。

## 却下した選択肢

- **`dev-author` をコアに残す**: 起動経路が無い定義を配布し、読み込み量だけを払う。レイヤー 3 の拡張を作る時点で必要になるが、その時点で拡張へ同梱すればよい。
- **`dev-author` を残したまま `install.py` に配布除外の指定を足す**: 除外の指定という機構を 1 件のために作ることになる。拡張固有エージェントの同梱経路(`extensions/README.md` 3.1)が既にあり、新しい機構を要しない。
- **コアを headless 対応にする**: 承認ゲートをすべて人間承認とする flow-sdd の設計を壊す。承認を自己承認へ置き換えた別の composition が要るが、それはレイヤー 3 の拡張ワークフローそのものである。
- **コアに全体の反復上限を書く**: 承認ゲートで停止する構成では上限に到達しない。自走の設計と一体で決めるべき値を、自走しない側に先に書くことになる。

## 帰結

- `dev/agents/dev-author.md` を削除した。
- `../../dev/skills/dev-core/references/orchestration-patterns.md` 5. の文書生成の項を、拡張が同梱するエージェントに委ねる形へ書き換えた。
- `../../dev/skills/flow-sdd/SKILL.md` 7.(対応しないこと)に headless 実行・Stop hook・全体の反復上限の扱いを追加した。
- `D-000-original-design.md` の 8.1(役割の構成)と 8.3(拡張固有エージェントが「レイヤー 0 の 5 役割」を上書きしない規律)に「→ D-022 で更新」を追記した。
- 導入済みの利用側では、`install.py core` の再実行が lock に記録した廃止分を削除する経路で `dev-author.md` が除かれる。再実行までは起動経路を持たない定義が残るだけで、動作には影響しない。
- `../DESIGN.md` の構成要素表からエージェント 1 件が減る(`meta-doc` による再生成で反映する)。
- dev-skills/004(並列実装の拡張バンドル)の前提が変わるため、同 issue のログへ記録する。

## 再検討条件

自走ワークフローの拡張を複数作る段になり、生成の隔離委譲を担うエージェントを拡張間で共有する必要が生じた場合(その時点でコアへ戻すかを判断する)。または flow-sdd 以外に、承認を持たない composition をコアへ置く要求が生じた場合。
