# D-004: DESIGN.md をテンプレート準拠の現状生成物にし、更新は全上書きにする(2026-07-14)

## 背景

D-001 で DESIGN.md を構造層(生成)+ 判断層(手書き)に分ける方針を立て、meta-doc を実装した(D-000 に初版 DESIGN.md を保存済み)。しかし再生成後も DESIGN.md には設計原則の散文・移行計画表・流用方針・前身プロジェクトへの外部引用など判断・履歴の記述が残り、構造層と判断層の境界が曖昧だった。差分追記で更新すると、どこが現状でどこが履歴か判別しにくく、ドリフトの温床になる。

## 決定

- DESIGN.md は**現状の構造のみ**を表す生成物とする。更新時は既存記述を**全上書き**する(差分追記をしない)。
- 履歴・設計判断の根拠は DESIGN.md に書かず、すべて `decisions/`(`D-###`)に残す。DESIGN.md からは `D-###` で参照する。
- DESIGN.md の構成をテンプレート(`meta-doc/templates/design-template.md`)で固定する。節は「概要 / 構成要素 / 相関図(レイヤー構造・DFD)/ 処理シーケンス」。
- 相関図・処理シーケンスは Mermaid で書く(レイヤー構造はネスト subgraph、DFD は flowchart、処理シーケンスは flow ごとの sequenceDiagram)。

## 却下した選択肢

- **DESIGN.md に判断記述を残したまま構造層だけ再生成する**: 現状と履歴が混在し、境界が曖昧なまま。D-001 の 2 層分離が名目化する。
- **判断記述を D-004 以降の個別判断へ逐一移設する**: 初版の設計思想の全文は D-000 に保存済みで、逐条移設は重複になる。現状生成物(DESIGN.md)と初版全文(D-000)+ 個別判断(D-001〜)で足りる。

## 帰結

- DESIGN.md をテンプレートに沿って全面再生成した(概要・構成要素の表・レイヤー構造/DFD の Mermaid・flow-sdd の処理シーケンス)。旧 DESIGN.md にあった設計原則の散文(§1〜§4)・移行計画(§5.2)・流用方針(§9)・実装計画(§10)・前身 `sdd/main` への外部引用は DESIGN.md から除いた(初版全文は D-000 に保存済み)。
- `meta_check.py` の外部参照 warning は DESIGN.md 分が解消し、D-000(初版の保存物)分のみ残る。
- meta-doc・principles.md(§3)・doc-perspectives.md を本方針に追随させた。

## 再検討条件

テンプレートの節構成が現状表現に不足すると判明した場合(テンプレートを更新して再生成する)。または Mermaid 以外の表現が要る図が生じた場合。
