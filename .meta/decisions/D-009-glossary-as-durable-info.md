# D-009: 恒久情報の配置に用語集を追加する(2026-07-26)

## 背景

恒久情報の配置規約(`durable-info.md`)は置き場を 6 種(コード・テストコード・コミットログ・ADR・doc コメント・README)に限り、「ここに挙げる置き場以外の恒久文書を作ってはならない」と定めていた。この一覧に語彙(プロジェクト固有の概念の呼び名)の置き場がない。

一方で、公開インターフェース・型の命名は dev-spec の壁打ちで作業単位ごとに確定し、その spec.md は実装完了で凍結される。命名の根拠が作業単位を跨いで残らないため、同じ概念に別の語が付く。

`contract-and-domain.md` はドメインモデルの完全性(貧血モデルの回避・不変条件)を扱うもので、語彙の統一は対象にしていない。出典: [mattpocock/skills](https://github.com/mattpocock/skills) の `CONTEXT.md` 形式(概念ごとの定義と `_Avoid_` を並べ、複数の呼び名があれば 1 つに決める)。

## 決定

- 恒久情報の配置先一覧に**用語集**(`docs/glossary.md`)を追加し、恒久文書の分類を 1 つ増やす。規約は `durable-info.md` 5. に置く。
- 形式は「概念ごとに 1〜2 文の定義 + `_Avoid:_`(使わない同義語)」とする。定義は何であるか(IS)を書き、何をするか(DOES)は書かない(振る舞いはコードとテストが表す)。収録はプロジェクト固有の概念に限り、一般的なプログラミング用語を入れない。
- 用語集とコードが食い違う場合、正はコードとする(「コードが SSoT」の適用)。どちらかに寄せ、食い違ったまま残さない。
- dev-spec Step 3 に、契約の命名を用語集と突き合わせる手順を置く。用語集ファイルへの追記は、dev-decompose が立てるドキュメント反映タスクで実装時に行う。
- 用語集の新規作成は強制しない。持たないプロジェクトでは既存コードの語彙に合わせる。

## 却下した選択肢

- **README に語彙の節を設ける**: README は「コード単位に紐づかない運用・横断方針」の置き場であり、性質が異なる。語彙は更新頻度と参照経路(契約の命名時に必ず引く)が README の他の記述と揃わない。
- **知識 port に置く**: port は利用側がプロジェクトごとに差し替える拡張点であり、注入のたびにコンテキストを消費する。語彙はプロジェクト内の恒久情報であって、注入して使う知識ではない。
- **spec.md に語彙節を持たせる**: spec.md は実装完了で凍結する中間生成物のため、作業単位を跨いで語彙を維持できない(この判断の前提そのものが成立しない)。

## 帰結

- `.claude/skills/dev-core/references/durable-info.md`: 配置先一覧へ用語集の行を追加し、形式と規律を 5. に定めた。
- `.claude/skills/dev-spec/SKILL.md` Step 3: 契約の命名を用語集と突き合わせる手順を追加した(用語集ファイルの更新は行わず、追加する語と定義を §8 へ記録する)。
- `.claude/skills/dev-decompose/SKILL.md` Step 3: ドキュメント反映タスクの対象に用語集を加えた(実際の追記はここで立てたタスクが行う)。
- `.claude/skills/dev-core/references/ports.md` 5.2: 知識 port へ昇格しない情報の判定を、durable-info.md の配置先一覧(用語集を含む)への参照にした。

## 再検討条件

用語集がコードの語彙から乖離したまま更新されない事象が続く場合。その場合は、識別子から用語集への機械的な照合(未収録語・`_Avoid:_` 語の使用の検出)を dev-check の検査観点へ加えることを先に評価する。
