# D-036: 禁止語を NG/OK 対のデータファイルへ外出しして拡充する(2026-08-23)

## 背景

japanese-writing の禁止語の情報は 3 箇所に分散していた。検出語は `lint.py` 内の定数 `FORBIDDEN_PHRASES`(48 語、2026-07 コーパス校正済み)、言い換えの指針は ext-writing-inspection の `rewrite_guides.json`(カテゴリ単位)、規範の列挙は `sentence.md` 7. が持つ。語を足すたびに 3 箇所の同期が要り、語ごとの OK 言い換え例(グッドパターン)はどこにも無かった。D-035 の元記事は、NG ルールごとに言い換え例を対で持たせると書き直しの精度が上がると述べる(「禁止だけを並べると、エージェントは避け方が分からず、不自然な回避文を書きがち」)。

## 決定

- **NG/OK 対のカタログ `scripts/forbidden_phrases.json` を正本として新設する**。語ごとに `ng`・`type`(型の分類)・`severity`・`ok`(言い換え例)・`note` を持つ。lint.py は検出語と severity をここから導出し(`FORBIDDEN_PHRASES`・`FORBIDDEN_PHRASES_WEAK_SIGNAL` はカタログ由来の導出値になる)、ext-writing-inspection の hook は語ごとの OK 例を読んで警告に添える(語を特定できない検出は従来どおりカテゴリ単位の `rewrite_guides.json` に落ちる)。
- **原典(coji/natural-japanese)のコーパス校正の判断をカタログへ引き継ぐ**。削除済みの語(「最後に」「まさに」)は `removed` に理由つきで記録し、弱いシグナルへの格下げ(5 語 → severity=info)は `note` に記録する。校正済みの語の severity はカタログでも変更しない。
- **拡充は既存資料からの段階拡充とし、40 語を追加する(計 88 語)**。出所は sentence.md 7. の拡張リスト(従来は目視確認扱い)・散文中で言及済みだが未検出だった語・元記事の設計。新語はコーパス未校正のため severity を保守的に付ける(info 15 語・warn 25 語)。warn の新語は ext-writing-inspection の既定で Stop のブロック対象になるため、締めの定型句・宣伝調など人間の技術文書にほぼ現れない語に限り、頻出語(「様々な」「劇的に」等)は info とする。
- **カタログの規約を 3 つ定め、テストで機械検査する**。語を重複させない・部分文字列で他の語を包含させない(`find()` 照合のため同一行での二重検出を生む)・全エントリが OK 例を持つ。
- **`sentence.md` 7. は型の分類・判断基準・代表例だけを残す**。網羅的な列挙はカタログへ移し、規範はカタログが育っても肥大しない形にする。
- **正当な用法が多い語はカタログに入れない**。元記事の最多検出語「効く」は、技術文書の正当な用法(「キャッシュが効く」)が多く部分文字列の照合では文脈を判定できないため、`sentence.md` 3.(不正確な動詞)の目視確認に残す。

## 却下した選択肢

- **lint.py 内の定数のまま拡充し、OK 例は rewrite_guides.json のカテゴリ指針に留める**: 語ごとの OK 例を持てず、元記事の知見(対のグッドパターンが書き直しの精度を上げる)を取り込めない。3 箇所の同期も残る。
- **sentence.md を正本にして lint.py が抽出する**: 規範文書が機械可読の制約(書式の固定)を負い、リライトのたびに検出が壊れうる。データと規範の役割を分ける。
- **rewrite_guides.json に語ごとの OK 例を持たせる**: カタログが検出語(japanese-writing 側)と OK 例(バンドル側)に割れ、語の追加が 2 リポジトリ相当の 2 箇所編集になる。検出と言い換えは同じ語に付く情報であり、1 ファイルに置く。
- **「効く」等の文脈依存語も severity=info で収録する**: info でも PostToolUse の警告は発火し、正当な用法のたびに書き直し指示が返る。誤検知の常態化は警告全体への信頼を下げる。
- **新語も warn を既定にする**: コーパス未校正の語が Stop の完了ブロックを起こす。校正済みの語と同じ扱いにする根拠がない。

## 帰結

- `writing/skills/japanese-writing/scripts/forbidden_phrases.json` を新設した(88 語 + removed 2 語 + 型 11 種)。
- `lint.py`: 定数リテラルを削除し、カタログからの導出に置き換えた。検出ロジック・severity・カテゴリは不変(fixtures の findings が行・カテゴリ・severity・excerpt まで一致することを確認済み。detail の注記文言のみカタログの note 由来に変わる)。
- ext-writing-inspection: `inspect_lib.py` に `load_phrase_okays()` を追加し、警告の検出行に「→ OK: …」を添える。カタログが読めない環境では従来どおりカテゴリ指針だけで成立する。
- `sentence.md` 7. を型の分類・判断基準・代表例に書き換え、8. に機械検出の所在を追記した。`inspection.md` 2.1・8. にカタログの正本を追記した。
- `tests/test_phrase_catalog.py`(カタログの整合と lint の導出)を追加し、`tests/test_inspection_hooks.py` に語ごとの OK 例の表示・フォールバックのテストを追加した。

## 再検討条件

新語が人間の文章への誤検知を起こす事例が観測された場合(該当語の info 格下げ・削除、またはコーパス再較正の導入を検討する)。カタログが数百語規模に育ち、型の分類や severity の管理が JSON の手編集で回らなくなった場合(登録スキル・週次分析の issue 化を早める)。
