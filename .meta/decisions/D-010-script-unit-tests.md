# D-010: スクリプトの単体テストを tests/ に置き、配布しない(2026-07-26)

## 背景

スキル群が同梱する決定論スクリプト(dev-core の state.py・check.py・lib.py・ports.py、meta-core の meta_check.py・meta_lib.py・meta_extract.py・meta_loc.py・trigger_check.py)にテストが無かった。

これらは状態遷移・承認ゲートの機械的強制・凍結のハッシュ照合・トレーサビリティ検査という、誤動作が全利用側プロジェクトへ波及し、かつ人間が退行に気づきにくい箇所を担う。実際、直前の meta-review では frontmatter 解析の誤判定(引用符つきの値を不一致と断定)と行数検査の無音の失効(基点が解決できないときに指摘 0 件で終わる)が見つかっており、いずれもケースを 1 つ置けば回帰として検出できる性質のものだった。

スキル群自体の品質(メタレベル)の原則は「同じ品質哲学を、適用対象を生成物からスキル群自体へ向け直す」ことにある。dev-implement は TDD を課し、`durable-info.md` は「実装完了後の受け入れ基準の正はテストコードである」と定める。スクリプトにテストが無い状態は、この原則の未適用にあたる。

## 決定

- 単体テストを**リポジトリ直下の `tests/`** に置く。`unittest`(標準ライブラリ)を使い、`python3 -m unittest discover -s tests -t tests` で実行する。
- テストは**配布しない**。`install.py core` は `.claude/skills/*` と `.claude/agents/*` をコピーするため、`tests/` は構成上その対象外になる(`meta-*` を配布しない D-006 と同じ扱い)。
- 実行を meta-check の手順に組み込む。スキル群自体に対する決定論的な検査の入口を 1 つに保つ(文書間の整合は meta_check.py、スクリプトの挙動は tests が担う)。
- テストは一時ディレクトリで自己完結させ、リポジトリ内のファイルを書き換えない。実リポジトリを対象にするのは read-only の検査に限る。
- 検出できることと誤検出しないことを対で書く。違反の検出だけを確かめると、常に検出する実装を通してしまう。

## 却下した選択肢

- **`meta-core/tests/` に置く**: `.claude/skills/meta-core/` 配下はスキルの実体であり、`install.py` の除外に依存して配布を防ぐことになる。除外条件が変われば配布物に混ざる。構成上そもそも対象外になる位置(リポジトリ直下)の方が安全である。加えて dev-core のスクリプトのテストが meta-core の下にあるのは所在として分かりにくい。
- **pytest を使う**: 追加インストールが必要になり、「スクリプトは Python 3 標準ライブラリのみで動作させる」という依存の規律と揃わない。テストの実行に別の前提を持ち込まない。
- **テストを書かず、機械検査の充実で代替する**: meta_check.py はスクリプトの入力ではなく文書を検査するもので、スクリプト自身の挙動は対象にできない(検査器の誤りは検査器では見つからない)。

## 帰結

- `tests/` を追加した(`helpers.py` + テスト 9 ファイル、190 ケース)。
- `.claude/skills/meta-check/SKILL.md` の Step 1 にテストの実行を追加した。
- テストの整備中に `meta_check.py` の `check_references` が、未解決のルートを渡されるとルート内の参照を外部参照と誤判定することが判明したため、解決済みのパス同士で比較するよう修正した。
- `README.md` の構成に `tests/` を追加した。

## 再検討条件

テストの実行時間が長くなって編集のたびに走らせなくなった場合(その時点で、実行を分ける・対象を絞るなどの構成を再設計する)。または配布物の構成が変わり、`tests/` が構成上の除外に当たらなくなった場合。
