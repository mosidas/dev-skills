# D-007: 多段オーケストレーションの禁止対象をエージェント主導に限定する(2026-07-26)

## 背景

中核原則(`orchestration-patterns.md`)は「サブエージェントは別のサブエージェントを呼ばない」を非交渉としていた。この記述は性質の異なる 2 つの形を 1 つの「多段」として扱っていた。

- **エージェント主導の多段委譲**: サブエージェントが自分の判断で次の委譲先を決める。委譲構造が実行前に定まらず、観測も制御もできない。禁止の根拠(文脈喪失・暴走・コスト膨張)はこちらに当たる。
- **スクリプト主導の多段オーケストレーション**: 委譲の段数・分岐・合流をスクリプトが定義する。構造がコードとして固定され、実行前に読める。

禁止を裏付ける根拠として挙げていた Claude Code の「サブエージェントは別のサブエージェントを起動できない」という制約は、エージェントによる委譲にのみ当てはまる。ワークフロー実行ツールのように、スクリプトから複数のエージェントを多段・並列に起動する機構では、この制約は多段の実行そのものを妨げない。

数十タスク規模の並列実装(作業ツリーを分離した並行実装と、合流点でのコンフリクト解決)を扱うには、依存グラフを実行計画へ変換して駆動する層が要る。この層は上記の後者に当たり、前者の禁止根拠が当てはまらない。出典: [Cursor, Agent swarms and the new model economics](https://cursor.com/blog/agent-swarm-model-economics)(planner の再帰分解と worker の階層、合流点を一元管理する調整機構)。

あわせて、旧世代のモデルを前提にした数値規定を点検した。「メイン文脈を約 500 行未満に保つ」の 500 行には根拠が記述されておらず、容量の逼迫を理由とする限りモデルの文脈長に依存する。

## 決定

- **禁止対象を「委譲先をエージェントが決めること」に限定する**。段数そのものは禁止しない。中核原則「単一オーケストレーター」とアンチパターン表(ペルソナ連鎖・深いペルソナ木)の記述をこの区別で書き分けた。
- **スクリプト主導の多段を支持パターン 7 として加える**。採用には 3 条件を課す。構造が実行前に読めること(各段のエージェントは次の委譲先を決めない)、合流点をスクリプトが一元管理すること、承認ゲートを跨がないこと(多段化してよいのは 1 つのゲートの内側に閉じる区間に限る)。
- **スクリプト実行機構に依存する実装は拡張(Layer 3)に置く**。コアの部品・composition は特定の実行機構を前提にしない(可搬性の担保)。これは D-000 §3 の依存規律(コアが使う実行機構をスキルとエージェント定義に限る)を、スクリプト実行の機構へ適用したものである。
- **「メイン文脈を約 500 行未満」の数値規定を撤廃し、判断基準へ書き換える**。メイン文脈に置くのはオーケストレーションの判断に使う情報(現在の状態・成果物の所在・構造化返却・分岐の根拠)に限り、調査対象の本文を展開しない。根拠を容量から「分岐の根拠を事後に特定できること」へ移し、モデルの文脈長と独立させた。
- 同じ理由で、`dev-implementer` の「それ以外の仕様文書・経緯を遡って読まない」制約の根拠を明記した。判断のドリフト抑止と、レビュー時の根拠特定である(いずれも文脈長と独立)。

## 却下した選択肢

- **多段を一律禁止のまま維持する**: 規模を拡大した並列実装を扱えない。禁止の根拠(観測性・制御性の喪失)はエージェント主導の場合にのみ成立し、スクリプト主導には当てはまらないため、根拠のない禁止が残る。
- **「メイン文脈を約 500 行未満」の閾値を現行モデル向けの数値へ更新する**: 数値を変えてもモデル更新のたびに再設定が要る。規律の目的が容量ではないため、判断基準へ書き換える方が保守できる。
- **スクリプト主導の多段をコア(Layer 1・2)でも使えるようにする**: 実行機構が harness 依存になり、配布先の環境を選ぶ。コアの可搬性を優先し Layer 3 に限定する。

- `orchestration-patterns.md`: 冒頭の補足・中核原則・支持パターン表・§2.2(パターン 7 の詳説)・アンチパターン表を更新した。
- `.claude/skills/dev-core/references/principles.md` §3(コンテキスト効率)・§6(オーケストレーション安全則): 調査の隔離と単一オーケストレーターの要約を追随させた。
- `.claude/agents/` の 5 定義: 安全エコーの文言を「委譲先を自分の判断で決めない」に統一し、`dev-explorer` の 500 行規定を撤廃した。`dev-implementer` に参照範囲の制約の根拠を追記した。
- 大規模並列実装の拡張スキル(依存グラフの実行計画への変換・作業ツリー分離・合流点のコンフリクト解決・並列実行中の共有メモ)は、本決定を前提に別途設計する。

## 再検討条件

スクリプト主導の多段で実行した作業に、観測性・制御性の欠落に起因する問題(どの段で何が起きたか特定できない・停止できない)が生じた場合。
