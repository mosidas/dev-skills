# D-020: 中断からの再開手順を固定し、巻き戻し手段を定める(2026-08-10)

## 背景

[Effective harnesses for long-running agents](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents) は、長時間エージェントの中心課題を「作業が離散的なセッションに分割され、各セッションが前回の記憶なしで始まること」と述べ、開始手順を「pwd → 進捗ファイルと git ログの読了 → `init.sh` 実行 → 基本機能のテスト → 未完了機能を 1 つ選択」の順で毎回実行することを求める。開始時のテストは前セッションが残した破損を早期に検出する目的を持つ。同記事は git のコミット履歴を進捗記録と復元点の両方に使い、不具合時は安定状態へ戻すことも挙げる。

本スキル群の現状(`../notes/2026-08-10-engineering-lenses.md` L-2・L-3):

- `flow-sdd/SKILL.md` Step 0 は「`state.json` があれば `status` で現在地を復元し、状態に対応するフェーズから続行する」と定めるが、順序を持つ手順ではなく、開始時の検証コマンド実行が無い。
- `git-convention.md` 1. は「誤った変更が起きても直前の状態へ復帰できる」ことを commit の目的に挙げるが、復帰の手順を書いていない。同 6. が `git reset --hard`・`git checkout .` を禁止しているため、禁止だけがあって復帰の実行手段が定義されていない。

## 決定

- **flow-sdd Step 0 を順序付きの再開手順にする**。順序は次のとおりとする。
  1. リポジトリの確認(git 管理下か)と現在のブランチの確認
  2. `state.json` の読み込み(`state.py status`)と直近の git ログの確認
  3. 検証コマンドの実行(前セッションが残した破損の検出)
  4. 状態に対応するフェーズの選択
- **検証コマンドは条件付きにする**。検証コマンドは `tasks.md` のタスク固有情報に書かれるため、`tasks.md` が無ければ実行対象が存在しない。条件は状態名ではなく**ファイルの実在**で判定する(状態は `tasks-generated` 以降だがファイルが無いという食い違いを、条件の外へ出して停止の対象にするため)。通常 `tasks.md` が無いのは `initialized`・`spec-generated`・`spec-approved` の 3 状態である。
- **git 管理下でない場合に省く範囲を明示する**。手順 2 の `git log` と手順 4 の `gh pr view` を省き、手順 3 は git に依存しないため実行する。
- **`git-convention.md` に巻き戻しの手順を足す**。コミット済みの変更は `git revert` で打ち消し(履歴を残す)、未コミットの変更は捨てずに `git stash` で退避する。破壊的操作の禁止(同 6.)と手段を対にする。

## 却下した選択肢

- **`init.sh` 相当の起動スクリプトの作成をコアで要求する**: 起動手順はプロジェクト側の資産であり、コアが作成を求めると可搬性を損なう。検証コマンドは `tasks.md` のタスク固有情報に既にあり、既存の情報で開始時検証が成立する。
- **全状態で検証コマンドを実行する**: `tasks.md` の生成前は実行対象が存在せず、手順が空振りする。
- **`git reset --hard` の禁止を緩め、巻き戻しに使う**: 未コミットの変更を失う操作であり、禁止の根拠(`../../dev/skills/dev-core/references/git-convention.md` 6. と `../../dev/skills/dev-implement/SKILL.md` 13.)は変わっていない。`git revert` と `git stash` で同じ目的を達せる。
- **checkpoint(`/rewind`)を巻き戻しの手段として規約に書く**: Claude Code の編集ツール経由の変更だけを追跡するため、スクリプト経由の変更や外部プロセスの副作用を戻せない。harness 固有の機構でもあり、コアの規約に置かない。

## 帰結

- `../../dev/skills/flow-sdd/SKILL.md` Step 0 を順序付きの再開手順に書き換え、検証コマンドの条件を明記した。
- `../../dev/skills/dev-core/references/git-convention.md` に 7.「巻き戻し(誤った変更からの復帰)」を追加した。6.(安全制約)と対になる位置へ挿入したため、以降の節を 8.(実行手順)・9.(PR 作成と CI 追従)・10.(注意)へ繰り下げ、他文書からの節番号の参照(`flow-sdd/SKILL.md` の §9、`.meta/` の 9.3・9.4)を追随させた。

## 再検討条件

`git revert` が競合で失敗し、`git-convention.md` の手順だけでは安定状態へ戻せなかった事例が発生した場合。または開始時の検証コマンドの実行時間が、1 作業単位の実装時間の 1 割を超えた場合(その場合は実行対象を差分に関係するテストへ絞る)。
