# D-017: 圧縮後の再開をファイルからの再導出で担保する(2026-08-10)

## 背景

[Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) は、上限に近づいた会話を要約して再開する際にアーキテクチャ上の決定・未解決のバグ・実装詳細を残すことを求める。[Best practices for Claude Code](https://code.claude.com/docs/en/best-practices) は `/compact <指示>` と CLAUDE.md の規則で要約の焦点を指定できると述べる。

dev-implement の自律モードは、dev-decompose 4. が定める規模上限の目安(1 作業単位のメインタスク 8 以下)まで反復するため、長い実行では圧縮が起きる。本スキル群には、圧縮時に何を残すかの指示も、圧縮後にどう再開するかの手順も無い(`../notes/2026-08-10-engineering-lenses.md` C-3)。

圧縮で失われる情報は 3 つの性質に分かれる。

| 性質 | 該当する情報 |
| ---- | ------------ |
| ファイルから再導出できる | 現在の状態、承認、完了・未完了のタスク、変更の履歴 |
| 再導出の入口になる | workdir のパス、`## Implementation Notes` の所在 |
| ファイルに無い | 直近の失敗の内容と原因、却下した方針 |

## 決定

- **主たる対策は再導出とする**。dev-implement と flow-sdd に「圧縮の後は、記憶ではなくファイル(`state.json`・`tasks.md`・git ログ)から現在地を再導出する」を書く。これは D-020 の再開手順を同一セッション内の圧縮にも適用するもので、harness の圧縮挙動に依存しない。
- **要約に残す情報の指定は補助とする**。workdir のパス・`## Implementation Notes` の所在・直近の失敗の内容と原因を挙げるが、これが効かなくても再導出で再開が成立する形にする。スキル本文の指定が圧縮の要約へ反映される機構は上記の出典に含まれておらず、**効果を確かめる手段を現時点で持たない**(圧縮は harness が任意の時点で起こすため、決定論的に再現できない)。評価シナリオ(`../evaluations/README.md` E-006)が確かめるのは主対策の側、すなわち要約に何も残らなくてもファイルから再導出できることである。
- **進捗ファイルを追加しない**(D-000 6.4 の中間生成物のライフサイクルを変えない)。

## 却下した選択肢

- **要約への指定だけを書く**: 指定が反映される機構を確認できていないため、再開の成否をその機構に依存させることになる。
- **利用側の CLAUDE.md に規則を書かせる**: 導入手順が増え、利用側の常時読み込み量も増える。スキル本文に書けば、導入しただけで効く。
- **進捗ファイル(`claude-progress.txt` 相当)を追加する**: 進捗の正本が `state.json`・`tasks.md`・git と重複し、どちらを正とするかの規律が新たに要る。再入時の現在地はこの 3 つから機械的に再導出でき、`orchestration-patterns.md` 1. の「再入時はファイルから現在地を機械的に再導出する」と一致する。
- **PreCompact hook で圧縮の直前に情報を注入する**: D-018 で hook の配布経路を作るため手段としては採れる。採らない理由は 2 点ある。hook は拡張バンドルの導入を条件とするため、導入しない利用側では効かず、主対策にできない。また圧縮後にファイルから再導出する手順があれば注入は不要であり、同じ目的に 2 つの機構を置くことになる。

## 帰結

- `../../dev/skills/dev-implement/SKILL.md` と `../../dev/skills/flow-sdd/SKILL.md` に、圧縮後の再導出手順と要約に残す情報を追加した。

## 再検討条件

圧縮の後にファイルから再導出しても再開できない事例(ファイルに残らない情報を必要とする作業)が観測された場合。または、圧縮の要約に何が残るかを決定論的に確かめる手段(harness が圧縮の入出力を提示する機構)が使えるようになった場合(その時点で補助の指定の効果を評価シナリオへ加える)。または自走ループ(レイヤー 3)の実装で、`state.json` と `tasks.md` から再導出できない情報を持ち越す必要が生じた場合。
