# D-027: `rm -rf` の禁止をリポジトリの中に限る(2026-08-13)

## 背景

D-018 は `rm -rf` を hook で拒否する対象に含めた。netdiver の unit #2 を実装した実運用で、この拒否が正当な作業を 3 回止めた(`1_issues/netdiver/007-mvp-core-loop/2026-08-12.md`。workspace 側の記録)。拒否されたのはいずれもリポジトリの外の削除で、目的は変異検査(実装を壊したときにテストが失敗するかの確認)のために使い捨ての複製を作ることだった。

```
cd /tmp && rm -rf kcheck && mkdir kcheck && ...
rm -rf /tmp/mutproj && mkdir -p /tmp/mutproj && rsync -a ...
MUT=$(mktemp -d) && cp -R ... && rm -rf "$MUT/.git" && ...
```

1 件目は拒否をきっかけにターンが `aborted_tools` で終了した。`ext-dev-guardrails` SKILL.md 5. は「拒否が正当な作業を止めた場合は、その事例を記録してバンドルの判定を見直す」と定め、D-018 の再検討条件も「hook が正当な操作を拒否した事例が観測された場合」としている。本判断はこれに該当する。

正本(`git-convention.md` 6.)が挙げる禁止の理由は「未コミット変更を失う操作」である。リポジトリの外の削除はこの理由に当たらない。

代替手段は実運用で確かめられており、指示に書いた後の拒否は 0 件になった(通るのは `rm -r`(`-f` なし)・`mktemp -d`・`git archive HEAD | tar -x -C "$MUT"`・`rsync -a --exclude .git`)。

## 決定

- **`rm -rf` の禁止をリポジトリの中に限る**。削除対象がすべてリポジトリの外だと確定できる場合は通す。正本(`git-convention.md` 6.)にこの限定を書き、hook の判定と一致させる(hook が正本にない禁止も、正本にない許可も持たない。D-018)。
- **判定できない対象は拒否する**。変数展開・コマンド置換・チルダ展開を含むパス、行き先を解決できない `cd` の後の相対パス、`.git` を持つ親ディレクトリが見つからない場合が該当する。復元できない操作であり、判定がつかないときに通すと守るべき場面を素通りさせるためである。
- **`cd` を追跡する**。セグメントを跨いで作業ディレクトリの移動を追い、相対パスの基点に使う。実運用で拒否された 3 件のうち 1 件が `cd /tmp && rm -rf kcheck` の形だったためである。
- **リポジトリ内は git の管理下かを問わず拒否する**。ビルド生成物・`node_modules` のような管理外のディレクトリも対象に含める。管理下かの判定には git の実行が要り、コマンド文字列の照合だけでは判定が閉じない(D-018 が hook の対象を「コマンド文字列とパスの照合だけで判定が閉じるもの」に限った条件から外れる)。該当する場合は `-f` を外した `rm -r` を使う。

判定の変更後、実運用で拒否された 3 件のうち 2 件が通る。3 件目(`rm -rf "$MUT/.git"`)は変数展開を含むため拒否のままだが、実測済みの代替手段(`git archive HEAD | tar -x -C "$MUT"` で `.git` を含めずに複製する)がある。

## 却下した選択肢

- **判定を見直さず、代替手段の周知にとどめる**: 代替手段は実在し拒否を 0 件にできるが、hook が正当な作業を止める状態が残る。禁止の理由(未コミットの変更を失う)がリポジトリの外に及ばない以上、その範囲の拒否には根拠がない。
- **`rm -rf` を hook の対象から外す**: リポジトリ内の再帰強制削除は未コミットの変更を失う操作そのものであり、禁止の根拠がある。範囲を狭めるべき場面で対象ごと外すと、守るべき場面まで通す。
- **判定できない対象を許可側に倒す**: hook の他の判定(入力を解釈できない場合)は許可側に倒すが、それは hook 自身の不具合で作業を止めないための扱いである。削除対象の不確定はこれと性質が違い、`rm -rf "$UNSET_VAR/"` のような形で守るべき場面を素通りさせる。
- **git の管理下かを `git check-ignore` で判定し、管理外なら通す**: `rm -rf node_modules` のような用法を通せるが、hook から git を実行することになり、D-018 が hook の対象に課した条件(コマンド文字列とパスの照合だけで判定が閉じる)から外れる。判定に外部プロセスの成否が加わり、その失敗時の扱いを新たに決める必要も生じる。

## 帰結

- `../../dev/extensions/guardrails/ext-dev-guardrails/hooks/guard_bash.py`: `_check_rm` が削除対象のパスを見るようにした。補助関数 `_resolve`(cwd 基点の絶対化。展開を含む語は解決しない)・`_repo_root`(`.git` を持つ親の探索)・`_inside_repo`・`_cd_target` を追加した。`check()` が `cwd` を受け取り `cd` を追跡する形にした。`main()` は PreToolUse の入力の `cwd` を読み、無ければ実行時の作業ディレクトリを使う。
- `../../dev/skills/dev-core/references/git-convention.md` 6.: `rm -rf` の禁止に「リポジトリ内を対象とする」の限定と、その理由・確定できない場合の扱いを書いた。
- `../../dev/extensions/guardrails/ext-dev-guardrails/SKILL.md`: 1. の表の記述を限定つきに改め、5.(判定の限界)に `rm -rf` のパス判定・確定できない対象の扱い・git の管理外も拒否することの 3 項を足した。
- `../../tests/test_guard_hooks.py`: `GuardBashRemovePathTest`(17 件)を追加した。既存の `assertDenied` / `assertAllowed` は `cwd` を受け取れるようにし、`sudo` の前置検査はリポジトリ内のパスを対象にして検査の意図(前置の読み飛ばし)を保った。

## 再検討条件

リポジトリ内の `rm -rf` の拒否が、git の管理外のディレクトリ(ビルド生成物等)に対する正当な作業を繰り返し止めた場合(`git check-ignore` による判定の導入、または対象からの除外を検討する)。または `cd` の追跡では基点を決められない用法(サブシェル・関数経由の移動)で誤った拒否が観測された場合。
