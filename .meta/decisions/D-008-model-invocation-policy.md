# D-008: 配布する部品をモデル自動起動の対象に置いたままにする(2026-07-26)

## 背景

Agent Skills 標準を実装する harness は、frontmatter の `disable-model-invocation: true` によってスキルをシステムプロンプトから隠し、ユーザーの明示起動(`/skill:name`)だけを許す。Claude Code と pi([earendil-works/pi](https://github.com/earendil-works/pi) `packages/coding-agent/docs/skills.md`)が同じキー名を解釈するため、これは特定 harness 固有の指定ではない。

dev-skills の配布物(`dev-*` / `flow-*`)はいずれもこのキーを持たず、モデルが自律的に起動できる。承認ゲートを持つ部品(dev-implement・flow-sdd)が、ユーザーの意図しない場面で自動起動しうるかを判断する必要があった。

## 決定

配布物はすべてモデル自動起動の対象に置いたままとする。`disable-model-invocation` を使わない。

根拠は 3 点である。

- **起動しただけでは外部に影響する操作が起きない**。dev-implement はタスク定義の確認から始まり、`tasks.md` が無ければ対話で確定してから進む。作業ブランチへのコミット・push はタスクのレビュー合格と検証成功を条件とし、破壊的な git 操作は禁止している。push は履歴を外部へ出す操作だが、作業ブランチに閉じ、main への統合は人間のマージに委ねられる。真に不可逆な操作(本番デプロイ)は dev-release が扱い、ユーザーの明示承認を必須とする。
- **承認ゲートは起動の可否とは別の機構が強制している**。gate 付きの状態遷移は `approve` でのみ通過でき、状態機械エンジンが機械的に担保する。起動の可否で重ねて防ぐ必要がない。
- **自動起動が現在の使い勝手を支えている**。「SDD で進めて」「実装を進めて」という依頼で該当部品が起動する経路は、モデル起動に依存する。

## 却下した選択肢

- **dev-implement と flow-sdd を `disable-model-invocation: true` にする**: 上記のとおり不可逆操作は別の機構で止まっており、得られる安全性に対して失う使い勝手が大きい。
- **利用側が選べるよう install.py にオプションを設ける**: 2 経路の保守コストに見合う利点がない(D-006 と同じ判断)。

## 帰結

配布物の frontmatter は変更していない(現状維持の判断のため、変えたものは無い)。判断の記録だけを残す。

## 再検討条件

依頼していない作業単位に対する commit / push、または本番環境への操作が、ユーザーが起動を意図していない場面で実際に発生した場合(「意図していない」の判定は、その作業を依頼した発話が無いことによる)。または配布物が増え、description の近接衝突がトリガ検査で実測された場合。
