社内 API のキャッシュ方式を 3 案で比較した。次の計測値をもとに、どの案を採用すべきかの調査レポートを `docs/report.md` に書いてほしい。

| 案 | p50 応答時間 | p99 応答時間 | キャッシュ命中率 | 月額費用 | 運用の手間 |
| :-- | --: | --: | --: | --: | :-- |
| A: アプリ内メモリ(LRU、上限 512MB) | 18ms | 240ms | 71% | 0 円 | 再起動でキャッシュが失われる。インスタンス間で内容が揃わない |
| B: Redis(マネージド、2 ノード) | 22ms | 95ms | 88% | 42,000 円 | 接続数の監視が必要。フェイルオーバーで 30 秒ほど命中率が下がる |
| C: CDN のエッジキャッシュ | 9ms | 310ms | 64% | 15,000 円 | 認証つきのレスポンスはキャッシュできない。パージに最大 60 秒かかる |

計測条件: 本番相当の負荷(秒間 1,200 リクエスト)で各案を 3 日間動かした。キャッシュなしの現状は p50 が 65ms、p99 が 410ms である。認証つきのリクエストは全体の 40% を占める。

この依頼への質問には答えられない。分からない点は自分で判断し、レポートを書き上げてほしい。
