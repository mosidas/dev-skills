# なぜ私たちはリトライを 3 回にしたのか

先月、決済 API の障害で 40 分間注文が止まりました。
原因はリトライでした。上流が遅くなった瞬間、全クライアントが即座に 5 回ずつ再送し、上流を完全に倒しました。

私たちが変えたのは 3 つです。
回数を 5 回から 3 回に減らしました。
間隔を指数的に伸ばし、ランダムなゆらぎ（jitter）を足しました。
そして、失敗率が 20% を超えたら再送そのものを止める仕組みを入れました。

正直に言うと、3 回という数字に強い根拠はありません。
障害時のログを見て、4 回目以降の再送が成功した例が 1 件もなかった、というだけです。

リトライは優しさのつもりで入れるものですが、全員が同時に優しくなると、それは攻撃になります。
