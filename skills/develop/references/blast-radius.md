# 差分の外の影響の点検

変更が差分の外で動かなくなる箇所を探し、変更の安全を支える 1 つの事実を確かさの段とともに示す手順を定める。reviewer はステップを点検するときに使う。gate-reviewer と統括は PR 本文の影響範囲を点検するときと書くときに使う(`git-flow.md` 3.)。もっともらしい説明は正しくても誤っていても同じように読める。だから事実の段と証拠を書く。

## 1. 適用範囲

- 本書の仕事は grep では届かない箇所を探すことである。呼び出し元の列挙は grep で済むので本書の仕事でない。呼び出し元を列挙して変更し終える規則は ponytail 2. が扱う。
- 品質を問わず適用する。品質が簡易のタスクでは段 4(実行した)を必須にしない(4.)。
- 性能の数値の確かさは `benchmark.md` が扱う。本書は変更が動かなくする箇所と安全の根拠だけを扱う。

## 2. 読む対象

grep で呼び出し元を確かめた後に次の 3 つを読む。

- ライブラリ: 呼ぶライブラリの実装を読む。読むのはアプリが固定した版(lock ファイルの版)の実装である。ローカルのパッチ(`patches/` の差分・フォークした依存)があればそれも読む。ドキュメントと別の版の実装は根拠にしない。
- 実行のタイミング: 処理がいつ実行されるかを確かめる。マイクロタスクの順・アンマウントと後始末の順・フレームワークの差(React と Solid の更新の違いなど)を見る。
- 記号の検索が届かないもの: 次のものは名前を grep しても見つからない。変更がそれらの形か意味を変えていないかを確かめる。
  - API が返す JSON の形
  - DB の列
  - ワイヤ形式(直列化した値・メッセージの形式)
  - 同じバイト列を読む別の言語のコード
  - フィーチャーフラグ
  - 3 段先のコード(呼び出し元の呼び出し元のさらに先)

## 3. 安全を支える 1 つの事実

危ないように見える変更の多くは 1 つの事実で安全になる。例は「この呼び出しは既に失効したキャッシュの項目だけを捨て、ほかに何もしない」である。その事実が成り立てば多くの危険がまとめて除かれる。時間は長い「かもしれない」の一覧でなくその事実に使う。

1. 変更を読む。差分・加えた記号・変えた記号・削除した記号を読み、変更後に何が違う動きをするかを書く。差分に書かれていない違い(既定値の変化・呼び出しの順の変化)も書く。
2. 安全を支える事実を 1 つの文で書く。1 つで足りないときも 2 つまでにする。
3. 本書 2. の読む対象でその事実を確かめ、4. の段を上げる。

## 4. 確かさの 5 段

| 段 | 名前 | 当たる証拠 |
| :-- | :-- | :-- |
| 1 | 言っただけ | 根拠を示さずに述べた。それだけでは価値が無い |
| 2 | 行を指した | 実在する `file:line` かライブラリの実装の行を示した |
| 3 | 到達しないと示した | 失敗の経路を 1 歩ずつ追い、失敗に届かないことを示した |
| 4 | 実行した | 実物のコードを呼ぶスクリプトかテストを実行した。事実が誤りなら大きく失敗する形である |
| 5 | アプリで再現した | 動いているアプリで事実を確かめた |

- 事実ごとに安く上げられる段まで上げる。報告にはどの段で止まったかと止まった理由を書く。
- 段 4 はアプリと同じライブラリを import して問題の関数を呼ぶ小さなスクリプト 1 本であることが多い。スクリプトは作業ツリーの外に書く。
- 品質が簡易のタスクでは段 4 を必須にしない。止まった段をそのまま書く。
- 段 1 のままの事実を安全の根拠にしない。段 2 に上げられなければ「未証明」と書く。

## 5. 危険の扱い

- 危険ごとに生じる確率と生じたときの損失を実際の値で書く。例: 「設定ファイルの無い初回の起動だけで生じる。生じると利用者の既定の言語が英語に戻る」。「まれに」「影響が大きい」だけで書かない。
- 確認した危険と確かめて除いた危険を分けて書く。除いた危険には除いた理由を書く。
- 根拠には実在する `file:line` を引く。
- 見つからなかった検索も答えである。検索のコマンドと範囲を書く。
- 呼び出し元と API を捏造しない。読んでいない箇所は読んでいないと書く。

## 6. 報告の形

reviewer は「確認したこと」に、統括は Implementation Notes に次の形で書く。PR 本文の影響範囲には安全を支える事実とその段だけを書く(`git-flow.md` 3.)。

```markdown
- 何をするか: <変更後に違う動きをすること。差分に書かれていない部分を含む>
- 安全を支える事実: <事実>。段: <1〜5 と名前>。証拠: <file:line・コマンドと出力>(証明できなければ「未証明」)
- 確認した危険: <生じる不具合>。<file:line>。確率: <値>。損失: <値>。確かめ方: <コマンドか手順>
- 除いた危険: <危険>。理由: <確かめた結果>
- マージ前の検査: <不具合を捕らえる最も安い検査か再現。書いたスクリプトを含む>
```

確認した危険と除いた危険が無ければ「なし」と書く。調べた範囲も書く。
