# HTML の説明資料の規範

## 1. 適用範囲

- 適用範囲は、HTML で配布する説明資料である。図・表・切り替えの UI(タブ・折りたたみ)を持ち、読み手がブラウザーで読む 1 ページの文書を指す。
- 次のものは対象外とする。
  - アプリの画面・フォーム・ダッシュボード。design-ui が扱う。
  - Markdown で配布する文書。write-doc が扱う。
  - スライド・プレゼン資料。write-slide が扱う。
  - 図だけの HTML 閲覧ページ。draw-diagram の `references/svg.md` 8. が扱う。
- HTML の資料は、文書であると同時に Web のページである。文書として扱って見た目を後回しにすると、実装の後に見た目の直しを何度も受ける。ページとして扱って本文を後回しにすると、推敲と検査が抜ける。本スキルは両方の工程を 1 つにまとめる。

## 2. 工程の一覧

| 工程 | 担当 | 成果 |
| :-- | :-- | :-- |
| 構成とモックの往復 | 統括(ユーザーとの対話) | 伝えたいことの 1 文、節の表、ページの構成のモック(HTML と PNG)、本人の合意 |
| 本文と図の作成 | 統括 | 節ごとの本文(Markdown)、図(`.mmd` と SVG) |
| HTML の生成 | 統括 | 本文と図から HTML を組み立てるスクリプトと、生成した HTML |
| 本文・図・スクリプト・見た目の検査 | 統括 | 本文の lint、図の照合、スクリプトの構文検査、スクリーンショットの目視の結果 |
| 別のエージェントによるレビュー | 別のエージェント(起動と仕分けは統括) | 別のエージェントの指摘と、「直した / 残す(理由)」の仕分け |

## 3. 工程の内容

### 3.1. 構成とモックの往復

- 読み手と目的を確かめ、伝えたいことの 1 文と節の表を書く(`../write-doc/references/paragraph.md` 3.)。読み手の分類は `../write-doc/references/readers.md` に従う。
- 節の表ができたら、ページの構成のモックを作り、本人と往復する。往復の形は design-ui の `../design-ui/references/session.md` の 3.1(案 1 つ・前回からの差分・質問 1 つ・往復の番号)、3.2(見せ方)、3.5(3 往復まで)に従う。3.1 の文言の表と brief は使わない。往復の記録は節の表の下に書く。
- モックに入れるのは、節の並び、図と表の位置、切り替えの UI(タブ・折りたたみ)の有無と位置、本文の行幅である。本文はダミーでよい。切り替えの UI は、モックでも JavaScript で動かしてよい(session.md 3.3 の「JavaScript を使わない」は適用しない)。
- モックの撮影は、3.4. の見た目の検査と同じ手順で行う。
- 合意した構成を、節の表に書き足す。

### 3.2. 本文と図の作成

- 本文は節ごとに Markdown で書き、`../write-doc/SKILL.md` の工程(書く・検査する)に従う。HTML に直接書かない。HTML に直接書くと、lint が本文を読めない。
- 図は `../draw-diagram/SKILL.md` の工程に従い、`.mmd` と SVG の対で作る。図の寸法は、ページの本文の幅で横スクロールを出さない値にする(`../draw-diagram/references/svg.md` 1.)。
- 表は Markdown の表で書く。

### 3.3. HTML の生成

- 本文の Markdown と図の SVG から HTML を組み立てるスクリプトを書く。スクリプトは、本文を変えたときに再実行できる形にし、HTML を手で直さない。
- 見た目は design-ui の閲読モード(`../design-ui/SKILL.md` 2.)に従う。トークンは `../design-ui/SKILL.md` 4. のスケールから選び、`../design-ui/references/anti-ai.md` と照合する。トークンには、本文の背景と別に、表と折りたたみの面の色を 1 つ持つ(4. の表の面)。
- CSS はインラインで書き、外部の資源(CDN・Web フォント)を読み込まない。配布先でネットワークが無くても読めるようにする。
- SVG は HTML にインラインで埋め込む。複数の図を埋め込むときは、`../draw-diagram/references/svg.md` 8. の接頭辞の規則(id と class に図ごとの接頭辞を付け、要素型セレクタと `:root` を使わない)に従う。svg.md 8. の雛形の HTML は使わず、本スキルの生成スクリプトで代える。
- JavaScript は、切り替えの UI(タブ・折りたたみ)に限って使う。本文の表示に JavaScript を要求しない。JavaScript が動かない環境でも、すべての本文と図が縦に並んで読める形にする。

### 3.4. 本文・図・スクリプト・見た目の検査

- 本文: 節ごとの Markdown に `../write-doc/scripts/lint.py` を実行し、`../write-doc/references/inspection.md` 4. の段落ごとの確かめと文書ごとの確かめを行う。
- 図: `../draw-diagram/scripts/render.py` で `.mmd` と SVG の対応を照合する。
- スクリプト: 生成スクリプトを `node --check <script>`(Node.js)か `python3 -m py_compile <script>`(Python)で構文検査する。生成した HTML の `<script>` の中身も、ファイルに抜き出して `node --check` にかける。生成スクリプトが通っても、埋め込んだ JavaScript の構文誤りは検出されない。
- 切り替えの UI: JavaScript を無効にした表示(全本文と図が縦に並ぶ形)を撮り、すべての節・表・図があることを確かめる。headless の撮影ではタブを押せないため、タブごとの表示は、本人に見せる前に統括がブラウザーで開き、各タブを順に押して表示先が変わることを確かめる。ブラウザーを開けない環境では、その旨を本人に伝える。
- 見た目: `../design-ui/references/session.md` 3.4. の手順で、生成した HTML を frames.html の iframe(幅 1280 と幅 390)に入れ、`render.py` の `screenshot()` でウィンドウ幅 1700 で 1 枚に撮る。headless Chrome はウィンドウを 500px 未満に縮めないため、幅 390 を直接は撮れない。高さは、ページ全体が入る値を引数で渡し、PNG の下端で本文が切れていたら上げて撮り直す。Claude Code では統括が Read で PNG を開いて点検し、画像を表示できない CLI では PNG のパスを示して本人に確かめてもらう。見るのは、横スクロール、図の縮小による文字の潰れ、表の面と背景の区別、切り替えの UI と表示先の位置である。design-ui の `../design-ui/SKILL.md` 3. の 5 と同じく、1 巡の確認、見つかった欠陥の一括修正、確認の 1 巡で止める。

### 3.5. 別のエージェントによるレビュー

- 他者向けの資料は、本人に見せる前に、書いたエージェントと別のエージェントにレビューさせる(`../write-doc/references/inspection.md` 5.)。渡すのは、節ごとの Markdown、生成した HTML、PNG、読み手、目的、規範である。
- レビュー役には、write-doc の観点に加えて、4. の HTML 固有の規則を渡す。

## 4. HTML 固有の規則

write-doc・draw-diagram・design-ui に無い、HTML の資料で守る規則である。

- 同じ種類の表は、列の並びと列の幅をそろえる。表ごとに列の位置が変わると、読み手は表を見比べられない。
- 一覧は省略せず、全件を縦に並べる。「n 件」「ほか」「など」で省略しない。一覧が長いときは、折りたたみに入れてよいが、中身は全件にする。
- 切り替えの操作(タブ・メニュー)と、切り替わる表示先を隣接させる。操作と表示先が離れると、読み手は何が切り替わったかを見失う。表と図を切り替えるときは、表と図を 1 つの UI に入れる。
- 同じ種類の要素は、折りたたみの有無をそろえる。候補 A の表を開いたままにして候補 B の表だけを折りたたむ、のような不ぞろいにしない。
- すべての表は、面(3.3. で持つ表の面の色)と枠線で本文の背景と区別する。面が背景と同じ色だと、行の境目が読めない。
- 折りたたみ(`<details>`)の `<summary>` のラベルは、見出しの規則に従う名詞句にする(`../write-doc/references/format.md` 1.)。
- 本文の行幅は、ページの本文の幅と同じにする。本文の幅より狭い位置で折り返さない。本文の幅そのものは、3.1. の往復で決める。
- 図は、本文の幅で横スクロールを出さない。横に長い図は、縦のスイムレーンに組み替えるか分ける(`../draw-diagram/references/svg.md` 1.)。
- タブ・行の分け方は、本文の節の分け方と 1 対 1 にする。本文が対象ごとに節を分けているなら、タブも対象ごとにする。
- 中間ファイルを参照しない(`../write-doc/references/readers.md` 3.)。前版の資料と、本ページに無い図も参照しない。版を改めるときは、前版の内容を本ページに取り込む。

| 規範 | 参照する範囲 | 参照しない範囲 |
| :-- | :-- | :-- |
| `../write-doc/` | 読み手・書式・文・段落・検査・別のエージェントによるレビュー(SKILL.md と references の全部) | なし |
| `../draw-diagram/` | 図の判断・工程・`.mmd`・SVG・`render.py`(SKILL.md と references の全部)。`references/svg.md` 8. は接頭辞の規則を参照する | `references/svg.md` 8. の雛形の HTML(本スキルの生成スクリプトで代える) |
| `../design-ui/` | 閲読モード(SKILL.md 2.)、スケール(4.)、階層と強調(5.)、構造は情報(6.)、`references/anti-ai.md`、`references/checklist.md` の共通と Web の節、`references/session.md` 3.1・3.2・3.4・3.5 | 操作・説得・体験のモード、`references/text.md`(利用者向けの敬体の文言。資料の本文は write-doc の常体)、`references/native.md`、`references/brief.md`、`references/session.md` 3.3 |

- 資料の中に画面のモックを載せるときも、モックの作り方は design-ui に従う。
- 往復での指摘は、retro の「本人の指摘」に含めない(`../design-ui/references/session.md` 6.)。実装の後に受けた見た目の指摘は含める。
