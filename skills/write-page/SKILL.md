# HTML の説明資料の規範

## 1. 適用範囲

- 適用範囲は、HTML で配布する説明資料である。図・表・切り替えの UI(タブ・折りたたみ)を持ち、読み手がブラウザーで読む 1 ページの文書を指す。
- 次のものは対象外とする。
  - アプリの画面・フォーム・ダッシュボード。design-ui が扱う。
  - Markdown で配布する文書。write-doc が扱う。
  - スライド・プレゼン資料。write-slide が扱う。
  - 図だけの HTML 閲覧ページ。draw-diagram の `references/svg.md` 8. が扱う。
- HTML の資料は、文書であると同時に Web のページである。文書として扱って見た目を後回しにすると、実装の後に見た目の直しを何度も受ける。ページとして扱って本文を後回しにすると、推敲と検査が抜ける。本スキルは両方の工程を 1 つにまとめる。

## 2. 工程

| 工程 | 担当 | 成果 |
| :-- | :-- | :-- |
| 構成とモックを往復する | 統括(ユーザーとの対話) | 伝えたいことの 1 文、節の表、ページの構成のモック(HTML と PNG)、本人の合意 |
| 本文と図を書く | 統括 | 節ごとの本文(Markdown)、図(`.mmd` と SVG) |
| 生成する | 統括 | 本文と図から HTML を組み立てるスクリプトと、生成した HTML |
| 検査する | 統括 | 本文の lint、図の照合、スクリプトの構文検査、スクリーンショットの目視の結果 |
| レビューさせる | 統括(別のエージェント) | 別のエージェントの指摘と、「直した / 残す(理由)」の仕分け |

### 2.1. 構成とモックを往復する

- 読み手と目的を確かめ、伝えたいことの 1 文と節の表を書く(`../write-doc/references/paragraph.md` 3.)。読み手の分類は `../write-doc/references/readers.md` に従う。
- 節の表ができたら、ページの構成のモックを作り、本人と往復する。往復の形は design-ui の `../design-ui/references/session.md` 3. に従う(1 往復に案 1 つ・差分・質問 1 つ、3 往復まで)。モックに入れるのは、節の並び、図と表の位置、切り替えの UI(タブ・折りたたみ)の有無と位置、本文の行幅である。本文はダミーでよい。
- モックの撮影は draw-diagram の `render.py` の `screenshot()` を使う(`../design-ui/references/session.md` 3.4.)。
- 合意した構成を、節の表に書き足す。往復の記録は節の表の下に残す。

### 2.2. 本文と図を書く

- 本文は節ごとに Markdown で書き、`../write-doc/SKILL.md` の工程(書く・検査する)に従う。HTML に直接書かない。HTML に直接書くと、lint が本文を読めない。
- 図は `../draw-diagram/SKILL.md` の工程に従い、`.mmd` と SVG の対で作る。図の寸法は、ページの本文の幅で横スクロールを出さない値にする(`../draw-diagram/references/svg.md` 1.)。
- 表は Markdown の表で書く。

### 2.3. 生成する

- 本文の Markdown と図の SVG から HTML を組み立てるスクリプトを書く。スクリプトは、本文を変えたときに再実行できる形にし、HTML を手で直さない。
- 見た目は design-ui の閲読モード(`../design-ui/SKILL.md` 2.)に従う。トークンは `../design-ui/SKILL.md` 4. のスケールから選び、`../design-ui/references/anti-ai.md` と照合する。
- CSS はインラインで書き、外部の資源(CDN・Web フォント)を読み込まない。配布先でネットワークが無くても読めるようにする。
- JavaScript は、切り替えの UI(タブ・折りたたみ)に限って使う。本文の表示に JavaScript を要求しない。JavaScript が動かない環境でも、すべての本文と図が縦に並んで読める形にする。

### 2.4. 検査する

- 本文: 節ごとの Markdown に `../write-doc/scripts/lint.py` を実行し、`../write-doc/references/inspection.md` 4. の段落ごとの確かめと文書ごとの確かめを行う。
- 図: `../draw-diagram/scripts/render.py` で `.mmd` と SVG の対応を照合する。
- スクリプト: `node --check <script>`(Node.js)か `python3 -m py_compile <script>`(Python)で構文を検査する。
- 見た目: 生成した HTML を `render.py` の `screenshot()` で幅 1280 と幅 390 の 2 枚撮り、Read で開いて点検する。見るのは、横スクロール、図の縮小による文字の潰れ、表の面と背景の区別、切り替えの UI と表示先の位置である。design-ui の `../design-ui/SKILL.md` 3. の 5 と同じく、1 巡の確認と一括修正で止める。

### 2.5. レビューさせる

- 他者向けの資料は、本人に見せる前に、書いたエージェントと別のエージェントにレビューさせる(`../write-doc/references/inspection.md` 5.)。渡すのは、節ごとの Markdown、生成した HTML、PNG、読み手、目的である。
- レビュー役には、write-doc の観点に加えて、3. の HTML 固有の規則を渡す。

## 3. HTML 固有の規則

write-doc・draw-diagram・design-ui に無い、HTML の資料で守る規則である。

- 同じ種類の表は、列の並びと列の幅をそろえる。表ごとに列の位置が変わると、読み手は表を見比べられない。
- 一覧は省略せず、全件を縦に並べる。「n 件」「ほか」「など」で省略しない。一覧が長いときは、折りたたみに入れてよいが、中身は全件にする。
- 切り替えの操作(タブ・メニュー)と、切り替わる表示先を隣接させる。操作と表示先が離れると、読み手は何が切り替わったかを見失う。表と図を切り替えるときは、表と図を 1 つの UI に入れる。
- 同じ種類の要素は、折りたたみの有無をそろえる。候補 A の表を開いたままにして候補 B の表だけを折りたたむ、のような不ぞろいにしない。
- 長い表は、面(`--panel`)と枠線で背景と区別する。面が背景と同じ色だと、行の境目が読めない。
- 折りたたみ(`<details>`)の `<summary>` のラベルは、見出しの規則に従う名詞句にする(`../write-doc/references/format.md` 1.)。
- 本文の行幅は、ページの本文の幅に合わせる。本文の幅より狭い位置で折り返さない。1 行の文字数の上限(全角 40〜45 字)は、本文の幅そのものを決めるときに使い、本文の幅の中でさらに折り返すために使わない。
- 図は、本文の幅で横スクロールを出さない。横に長い図は、縦のスイムレーンに組み替えるか分ける(`../draw-diagram/references/svg.md` 1.)。
- 切り替えの UI の役割(人・AI・システムの行、業務フローごとのタブ)は、本文の軸と 1 対 1 にする。本文が業務フローごとに分かれているなら、タブも業務フローごとにする。
- 前版の資料・中間ファイル・本ページに無い図を参照しない(`../write-doc/references/readers.md` 3.)。版を改めるときは、前版の内容を本ページに取り込む。

## 4. 参照する規範

| 規範 | 参照する範囲 | 参照しない範囲 |
| :-- | :-- | :-- |
| `../write-doc/` | 読み手・書式・文・段落・検査・別のエージェントによるレビュー(SKILL.md と references の全部) | なし |
| `../draw-diagram/` | 図の判断・工程・`.mmd`・SVG・`render.py`(SKILL.md と references の全部) | `references/svg.md` 8. の HTML 閲覧ページの雛形(本スキルの生成スクリプトで代える) |
| `../design-ui/` | 閲読モード(SKILL.md 2.)、スケール(4.)、階層と強調(5.)、構造は情報(6.)、`references/anti-ai.md`、`references/checklist.md` の共通と Web の節、`references/session.md` 3. の往復の形 | 操作・説得・体験のモード、`references/text.md`(利用者向けの敬体の文言。資料の本文は write-doc の常体)、`references/native.md`、`references/brief.md` |

## 5. 他スキルとの関係

- 資料の本文と図の規範は本スキルで定めず、write-doc と draw-diagram を参照する。本スキルが定めるのは、工程の順序と HTML 固有の規則である。
- アプリの画面の設計は design-ui に従う。資料の中に画面のモックを載せるときも、モックの作り方は design-ui に従う。
- 往復での指摘は、retro の「本人の指摘」に含めない(`../design-ui/references/session.md` 6.)。実装の後に受けた見た目の指摘は含める。
