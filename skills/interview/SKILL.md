# 着手前の聞き出し

本スキルは統括が読む。統括は実装・文書・PRD のどれに着手する前でも本人に 1 問ずつ聞いて作るものと読み手に判断してもらうことの曖昧さをなくす。そのうえで呼び出し元の出力の形に書いた答えと答えの出なかった問いを成果として返す。いつ終えるかと答えの書き先は呼び出し元が持つ。ファイルは書き換えない。答えを書くのは呼び出し元の手順である。

## 1. 適用範囲

- 呼び出し元は 3 つある(5.)。呼び出し元を持たずに本人が直接呼んだときは何のために聞くか(実装・文書・PRD)を最初の 1 問にする。答えに当たる呼び出し元の手順へ入る。
- 聞くのは「何を作るか」と「誰に何を判断してもらうか」に限る。「どう作るか」は聞かない。実装では planner が判断する(`../develop/references/requirements.md` 2.)。文書では書き手が判断する。
- 問いの数の上限は持たない。上限と打ち切りは呼び出し元の終了条件と本人の指示に従う。

## 2. 聞き方

- 1 問ずつ聞く。答えで次の問いが変わるためである。一度に並べると前の答えで不要になった問いにまで本人が答えることになる。次に聞く問いは答えが残りの問いを最も多く変えるものにする。まだ答えの出ていない問いを前提にする問いは後に回す。
- 調べて分かることは聞く前に調べる。本人の時間を調べれば分かることに使わないためである。対象のリポジトリと既存の文書と前の会話で答えが出る問いは先に調べる。試して分かることは先に試す。調べた結果は本人に示して確認を得る。判定の問いは「本人しか知らないことか本人が判断することか」である。どちらでもなければ聞かない。
- 本人が判断することを統括が答えて先へ進まない。事実を調べるのは統括の仕事であり判断は本人の仕事である。統括が本人の判断を代わりに答えると聞き出した結果は本人の考えでなく統括の意見になる。
- 問いには統括の推奨と根拠を 1 行で付ける。問いは「はい」で推奨を受け入れられる形に書く。本人は返答だけで答えられる。
- 本人の答えを評価する言葉(「いいですね」など)を挟まずに次の問いへ進む。評価を挟むと本人の次の答えが統括の好む方向へ寄る。
- 推測で埋めない。答えが出ない問いと本人が後回しにした問いは未決として残して次の問いへ進む。
- 5〜8 問ごとに埋まった項目・未決の問い・今聞いている項目を本人に示す。本人は進み具合を見て打ち切るかどの項目を先に聞かせるかを判断できる。
- 本人が打ち切ったらその時点で聞くのをやめる。埋まっていない項目と未決の問いを呼び出し元の出力の形で残す。

## 3. 問いの型

問いは次の 9 つの型から作る。上の 5 つは実装と文書の両方に通る。下の 4 つは読み手のいる成果物のための型である。実装でも誰の何を解決するかを確かめるときに使う。答えは表の書き先に書く。PRD の書き先は specify 2. に従う。

| 型 | 問い | 実装での書き先 | 文書での書き先 |
| :-- | :-- | :-- | :-- |
| 範囲 | これは対象内か対象外か | 要件の対象外の行 | brief の目的と節の表(入れる節・削る節) |
| 境界 | この入力・状態のときはどうなるか | 完了条件 | 節の表(条件ごとに扱いを分ける節) |
| 失敗 | 失敗したとき利用者は何を見てどう復旧するか | 完了条件(失敗時の挙動) | 節の表(失敗時の手順を書く節) |
| 順序と依存 | 先に必要なものは何か | Notes の決定事項(前提とするもの) | 節の表の並び(前提を説明する節を前にする) |
| 代替 | なぜこの方法か | Notes の決定事項(見送った案と理由) | 節の表(比べた案を書く節) |
| 読み手 | 誰が読むか・使うか。その人は何を知っているか | 目的の「誰」 | brief の読み手 |
| 判断してもらうこと | 読み手に何を判断してもらうか・何をしてもらうか | 目的の「何を解決するか」 | brief の目的と節の表の役割 |
| 反論 | 読み手はどこを疑いどこに反対するか | Notes の決定事項(反論への答え) | 節の表(反論に答える節) |
| 根拠 | その主張と完了を何が示すか | 完了条件の確かめ方 | 節の表(根拠の出典・数値を示す節) |

## 4. 終える

いつ終えるかは呼び出し元の終了条件に従う。聞き続けるかの判定の問いは「残る問いを本人が答えずに統括が判断しても本人が直させないか」である。直させると思う問いが残るうちは聞く。呼び出し元の上限に達したらその問いを未決として本人に示す。

終えるときは埋まった項目と未決の問いを示して本人の確認を得てから呼び出し元の次の工程へ進む。問いが尽きても本人と同じ理解に達したとは限らない。

## 5. 他スキルとの関係

- specify 2. が PRD を書く前に使う。終了条件は specify 4. にあり書き先は PRD の各節である。
- develop 2. が使う。本人が「詰めて」と言ったときと完了条件の確かめ方を統括が補えないときである。答えは要件の 4 行と Implementation Notes の決定事項に書く。
- write-doc の `../write-doc/references/process.md` 2. が使う。brief を既定値で埋められないときと本人が「詰めて」と言ったときである。答えは brief と節の表(`../write-doc/references/paragraph.md` 3.)に書く。
