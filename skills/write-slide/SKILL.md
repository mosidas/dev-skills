# スライド構成の規範

## 1. 適用範囲

スライド・プレゼン資料・発表資料・説明資料(読み返す用のスライド)・Marp の構成を作る・直す作業に適用する。規則の正本は write-doc の references にあり、本スキルは読むファイルとスライド固有の工程だけを定める。

## 2. 読むファイル

次の順に読む。

| ファイル | 扱う規範 | 読むとき |
| :-- | :-- | :-- |
| `../write-doc/references/process.md` | 工程の一覧、brief、骨組みの合意、疑問の一覧、肉付けの規則、指摘を受けた後 | 書き始める前と、工程を進めるとき |
| `../write-doc/references/format/slide.md` | 型(プレゼン型・説明資料型)、メッセージライン、タイトル、ページの作り方、文体と強調 | 構成を決めるときと、ページを書くとき |
| `../write-doc/references/sentence.md` | 語の選び方、文の組み立て、事実・意見・確信度、表記、出典 | タイトル・メッセージライン・本体の文を書くとき |
| `../write-doc/references/paragraph.md` | 箇条書き、論証、構成、接地と省略、見出し、表と図 | ページの役割を決めるときと、本体を組むとき |
| `../write-doc/references/inspection.md` | 検査スクリプト、文書ごとの確かめ、別のエージェントによるレビュー | 書いた後に点検するとき |

## 3. スライド固有の工程

- 型(プレゼン型・説明資料型。`format/slide.md` 1.)のどちらで作るかを、書き始める前にユーザーに確かめる。
- 骨組みの合意(`process.md` 3.)の節の表は、ページ単位で作る。
- 検査はスケルトン通読で行う。プレゼン型はメッセージラインだけを順に読み、論旨と結論の言い切りを確かめる。説明資料型はタイトルだけを順に読み、章の並びと各ページの守備範囲が読み取れるかを確かめる。
- 図は `format/slide.md` 5. の規則に従い、draw-diagram の工程で SVG を描く。

## 4. 扱わないこと

配色・文字サイズ(pt)・版面の寸法と、HTML・PPTX・Marp での実装(テーマ・CSS クラス・PDF の生成)は本スキルが扱わない。
