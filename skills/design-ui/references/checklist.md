# 実装の品質床

機械的に確認できる規則の一覧である。実装後に、この一覧に沿って点検する。1〜3 節は媒体を問わない共通の規則、4〜9 節は Web 固有の規則である。ネイティブアプリ固有の規則は `native.md` が定める。

## 1. アクセシビリティ(共通)

- 通常サイズの文字のコントラストは 4.5:1 以上、大きな文字(24px 通常または 18.66px 太字以上)は 3:1 以上を確保する。
- アイコンだけのボタンには、読み上げ用の名前(Web は `aria-label`)を付ける。装飾のアイコンは読み上げの対象から外す(Web は `aria-hidden="true"`)。
- 色だけで意味を示さない。アイコン・形・文言のいずれかを併用する。
- 画像には代替テキストを付ける。装飾画像は読み上げの対象から外す(Web は `alt=""`)。

## 2. 状態とモーション(共通)

- 部品の状態として、hover・focus・disabled・loading・error・empty を実装時にすべて用意する。モバイルアプリでは hover を除く 5 状態を用意する。
- 画面と操作の状態として、待機・読み込み中または送信中・成功・失敗(利用者が直せるものと直せないものを分ける)・空・タイムアウト・オフラインのうち該当する状態を用意し、各状態に利用者が次に取れる行動を示す。読み込み中・失敗・空の画面では、部品の loading・error・empty の表示を使う。失敗の状態の洗い出しは、品質がプロダクトのとき recover に従う。
- 送信ボタンは、リクエスト開始まで無効化しない。開始後にスピナーで進行を示す。
- エラーは、原因が解消するか利用者が閉じるまで表示を続ける。フォームと操作のエラーは該当する箇所か、利用者が閉じられる通知に出し、保存・決済・検証の失敗を、一定時間で表示されなくなるトーストだけで知らせない。一定時間で表示されなくなるトーストは、他の場所でも見返せる重要でない通知だけに使う。理由は、一定時間で表示されなくなるエラーは、利用者が読む前か直す前に見えなくなるためである。
- 長いコンテンツ・空の配列を想定して、レイアウトが崩れないことを確認する。
- `prefers-reduced-motion`(ネイティブアプリは OS のモーション低減設定)を尊重し、動きを抑えた代替か無効化を用意する。

## 3. フォームの入力と検証(共通)

- 欄の検証は、利用者が入力してその欄を離れた後に初めて行う。フォーカスを得た時点、入力し始めた時点、何も入力せずに欄を離れた時点では検証しない。未入力の必須欄は送信時に示す。文字数の上限やパスワードの条件のように入力中に必要になる規則だけを、入力中に示す。理由は、入力を終える前に誤りと示すと、まだ誤っていない利用者を責めることになるためである。
- エラーを示した欄は、その後は入力のたびに検証し直し、値が正しくなった時点でメッセージとエラーの見た目を外す(Web は `aria-invalid` も外す)。次の送信や欄を離れる時点まで待たない。依存する欄も検証し直す。確認用のパスワードの欄がこれに当たる。再送信のときはすべての欄を検証し直し、エラーの一覧を出しているなら解消した項目を一覧からも外す。初回の検証は前の項目のとおり欄を離れた後に行う。入力のたびの検証は、エラーを示した後の欄、その欄に依存する欄、前の項目の入力中に必要になる規則に限る。理由は、直した値にエラーが残ると、正しい入力が誤りに見え続けるためである。
- 検証かサーバーのエラーで送信に失敗したら、正しい欄も誤った欄も、利用者が入力した値のまま表示し直し、直すべき欄だけにエラーを示す。フォームを空にせず、失敗した欄の値も削除せず、空のフォームを読み込み直さない。パスワードのような秘密の欄は空にしてよい。理由は、入力した値を削除すると、利用者に入力し直しを強いるためである。
- 未保存の変更の有無を状態として持ち、未保存の変更があるときは、画面の遷移・ダイアログを閉じる操作・キャンセルの前に、変更を破棄してよいかを確かめる。選択肢は「変更を破棄」「編集を続ける」のように結果を言う。Web でタブを閉じる操作には `beforeunload` で確かめる。変更が無いときと保存が成功した後は確かめない。`text.md` 4. は復旧できる操作に確認でなく取り消しを求めるが、破棄した編集は取り消しで戻せないので、確認を取る側に当たる。理由は、確かめずに閉じると、利用者が気づかないうちに編集が失われるためである。
- 入力の書式に寛容にする。前後の空白を除き、番号とコード(電話番号・カード番号など)の空白・ハイフン・括弧を無視し、全角の数字と記号を半角にそろえ、名前のアクセント・ハイフン・アポストロフィを受け付ける。正規化してから検証し、誤った値か曖昧な値だけを拒否する。理由は、正しい値を書式の違いで拒否すると、利用者には直しようのないエラーになるためである。

## 4. Web: 操作とフォーカス

- 操作には `<button>`、ページ遷移には `<a>` を使う。`<div onClick>` を操作の代わりにしない。
- 操作対象には `:focus-visible` で可視のフォーカスを与える。
- `outline: none` を、代替のフォーカス表示を用意せずに使わない。
- 複合コントロールは `:focus-within` でグループ化する。
- 固定ヘッダー・フッター・オーバーレイが、フォーカス中の要素を覆わないようにする。
- モーダルを開いたらフォーカスを中に移し、開いている間は Tab と Shift+Tab を中に留め、Escape で閉じ、閉じたら開いた部品へフォーカスを戻す。開いた部品が無くなっていたら、ページの先頭でなく次の論理的な要素へ戻す。手段の例として、`<dialog>` の `showModal()` はフォーカスの移動と留め置きを持つ。理由は、フォーカスが背後のページに残ると、キーボードと読み上げの利用者がモーダルを操作できないためである。

## 5. Web: タッチとフォーム

- タップ領域は 44×44px 以上を確保する。視覚上のアイコンが小さいときは、当たり判定だけ広げる。
- ラベルは常時表示にする。placeholder だけをラベルの代わりにしない。
- エラーは該当フィールドの脇に表示し、送信時に最初のエラーへフォーカスを移す。
- `onPaste` で貼り付けを止めない。
- 適切な `autocomplete`・`inputmode`・`type`(email、tel、url、number)を指定する。
- キーの処理で Enter を送信や検索に割り当てた入力欄では、次の順に判定する。修飾キー付きの Enter は送信の処理より先に通し、Shift+Enter の改行のようにアプリが決めた扱いに任せる。扱う Enter は既定動作を止めてから、変換中なら送信しない。変換中かは `event.isComposing` か `keyCode === 229` で判定する。キーの長押しによる繰り返しも、`event.repeat` で判定して送信しない。Enter のたびに入力欄を空にせず、`compositionend` を送信の契機にしない。仮想キーボードで送信できるよう、送信ボタンを残す。理由は、日本語・中国語・韓国語の入力では変換の確定に Enter を使い、確定の Enter で書きかけの文が送信されるためである。

## 6. Web: アニメーション

- アニメーションは `transform` と `opacity` を中心に、コンポジタで処理できる性質のプロパティに絞る。
- `transition: all` を使わず、対象のプロパティを列挙する。

## 7. Web: 記号と数字

- 省略は `...` でなく `…` を使う。
- 数値の桁をそろえる場面では `font-variant-numeric: tabular-nums` を使う。
- 単位の前には改行させたくない空白(`&nbsp;` など)を入れる。
- 日付・数値・通貨は `Intl.DateTimeFormat`・`Intl.NumberFormat` で整形し、書式を決め打ちしない。

## 8. Web: レイアウト

- 横スクロールを、意図した領域以外に発生させない。`overflow-x: hidden` で防ぐ場合は、原因側の崩れも直す。
- flex の子要素にはテキストの省略を許すため `min-width: 0` を指定する。
- ライトとダークの両方のテーマで、コントラストと境界線の視認性を個別に確認する。
- 見出しと短い中央寄せのブロックに `text-wrap: balance`、本文に `text-wrap: pretty` を指定する。対応しないブラウザーでは既定の折り返しのままになる。`pretty` は最終行に 1 語だけ残ることを避けるだけで、最終行を埋めない。どちらでも直らない狭い段は、文言か段幅を直す。
- 見出しを手動で改行するときは、句(文節)の間だけで改行し、見出しが表示されるすべての幅で、手動の改行が行の途中に来ていないことを確かめる。UI モックでは `session.md` 3.4 の幅 1280 と幅 390 で確かめる。実装では両端の 2 幅で済ませず、最も狭い幅から最も広い幅まで幅を連続して変えて確かめる。行の途中に来る手動の改行は、既定の折り返しより読みにくい。不揃いな改行(1 語だけを残す見出し・引用)は意図した箇所に限り、稀にとどめる。
- 日本語では最終行に 1 語だけ残ることは起きにくいが、`balance` の指定と、見出しが文節の途中、つまり語と助詞の間や語の途中で折れていないかの確認は当てはまる。`lang="ja"` を指定した見出しに限り `word-break: auto-phrase` を使ってよい。`auto-phrase` は言語の指定が無いと文節で折り返さない。対応するのは Chromium だけで、他のブラウザーは既定の折り返しになる。

## 9. Web: パフォーマンス

- 画像には `width`・`height` を明示し、読み込み中のレイアウトのずれ(CLS)を防ぐ。
- ビューポート外の画像は `loading="lazy"` にする。上部の主要な画像は先読みする。
- 50 件を超える一覧は仮想化するか、`content-visibility: auto` で描画範囲を絞る。
