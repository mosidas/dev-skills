# 読み取りだけの調査

本スキルは統括が読む。統括はコードを変えずに問いに答える。成果は応答だけである。調べる対象の作業ツリーとリポジトリと課題管理とチャットの状態は調べる前と後で同じである。

## 1. 適用範囲

- 次の種類の問いに使う。振り分けは 2. の表に従う。
  - 仕組み: X はどう動くか。この処理はどのモジュールに属すべきか。
- 書き込まない。ファイルの編集・コミット・push・課題とチャットへの投稿をしない。守るものは本人の作業ツリーと共有の記録である。判定の問いは「この操作の後に本人が戻す必要のある差分が残るか」である。大きな出力は作業ツリーの外のファイルに書く。
- 調べる途中で直す点が見つかったら応答に書く。直すのは develop である。
- 問いの対象が曖昧なときは会話(開いているファイル・直前の変更・話題)から解釈を 1 文で書いて進める。本人が違うと言えば対象を替える。

## 2. 工程

| 工程 | 担当 | 成果 |
| :-- | :-- | :-- |
| 振り分ける | 統括 | 問いの種類と対象を書いた 1 文 |
| 調べる | 探索役(単純な問いでは説明役。Codex CLI・Antigravity CLI では統括) | 所見(複雑な問いでは切り口ごと) |
| まとめる | 説明役(Codex CLI・Antigravity CLI では統括) | 問いの種類ごとの出力の形で書いた説明 |
| 示す | 統括 | 本人への応答 |

問いの種類は次の表で振り分ける。

| 問い | 例 | 手順 | 出力 |
| :-- | :-- | :-- | :-- |
| 仕組み | X はどう動くか | `references/how.md` | 概要・主要な概念・動き・所在・落とし穴 |

## 3. 共通の作法

Claude Code では役ごとに次のサブエージェントを使う。

| 役 | `subagent_type` | 使う問い |
| :-- | :-- | :-- |
| 探索役 | `Explore` | 仕組みの複雑な問い |
| 説明役 | `general-purpose` | 仕組み |

- `Explore` は抜粋を読んで所在を探す役である。ファイル全体を読んで照合する役には `general-purpose` を使う。`general-purpose` は書き込みの道具を持つ。そのためブリーフに書き込まない指示を書く。各雛形にはその指示を書いてある。
- 並列に起動するときは develop の `references/parallel.md` 2. の作法に従う。同じブリーフ・単独で読めるブリーフ・1 つのメッセージでの起動・脱落・報告の規則を使う。本スキルの役は書き込まないので書き込み先の分離(worktree)は使わない。
- Codex CLI・Antigravity CLI ではサブエージェントを起動しない。統括が切り口を 1 つずつ順に調べる。所見は探索役の雛形の報告の形で書く。次に説明役の雛形の出力の形で統括がまとめる。並列の起動を省いたことを 1 行で報告する(develop の冒頭の段落と同じ扱い)。

## 4. 他スキルとの関係

- develop: コードを変える依頼は develop が扱う。調査で直す点が見つかったら develop の要件の確認から始める。
- `agents/planner.md`: planner は計画の「関係するコードの仕組み」の節を書く。節の構成は仕組みの問いの出力と同じ 5 節である。本スキルは計画を伴わない問いに答える。
- develop の `references/blast-radius.md`: 変更の影響を点検する手順である。本スキルは変更を伴わない問いに答える。
- draw-diagram: 図の列の規則は draw-diagram 1. にある。本スキルは引くだけである。
