# 日本語ライティング規範

## 1. 工程

本スキルは、日本語で開発ドキュメントや技術文書を書く・推敲するときの規範を定める。規範の本文は `references/` の各ファイルに置き、作業に必要なファイルだけを読む。

- 読み手を確認する: 本人向けか他者向けかをユーザーに確かめる(`references/readers.md`)。
- 書く: 表記・書式(`references/format.md`)、文・語彙(`references/sentence.md`)、段落・構成(`references/paragraph.md`)を制約として本文を書く。
- 検査する: lint.py 等で機械検出し、構造と事実は目視でレビューして、「直した / 残す(理由)」に仕分ける(`references/inspection.md`)。

既存文書の推敲・リライトでは、対象の粒度に応じたファイルだけを適用する。一文の修正に構成の規範までは適用しない。

## 2. 参照ファイル

| ファイル | 扱う規範 | 読むとき |
| :-- | :-- | :-- |
| `references/readers.md` | 読み手の分類(本人向け・他者向け)と、分類ごとに省いてよいもの | 書き始める前 |
| `references/format.md` | 文書構成と見出し、表記、記号、コード例と参照 | 本文を書く・直すとき |
| `references/sentence.md` | 語の選び方、文の組み立て、動詞と語彙、事実・意見・確信度、翻訳調 | 本文を書く・直すとき |
| `references/paragraph.md` | 段落、論証の厳密さ、構成、接地と省略、スケルトン通読 | 段落・章節を書く・点検するとき |
| `references/inspection.md` | 検査スクリプトと hooks の使い方、検出への対応、判断台帳、収束条件 | 書いた後に点検・推敲するとき |

- 検査スクリプトは `scripts/` にあり、`uv run` で実行する(依存はスクリプト内で宣言済み)。
- 文書に図を載せるときは diagram-authoring に従う。本スキルは図の書式(`references/format.md` 4.)だけを扱い、図にする内容と描き方は扱わない。

## 3. 優先規則

- 書式(`references/format.md`)は文章品質の規範より優先する。
- 引用・参考文献のタイトルなど、原典の表記を保つべき箇所は本規範に従わなくてよい。
- 規範どうしが衝突するときは、読み手の得になるほうを選ぶ。
