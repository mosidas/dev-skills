# 議事録

本ファイルは、議事録(会議で話したこと・決めたこと・アクションアイテムを残す文書)の決まりを定める。

## 1. 読み手

読み手は出席者と欠席者である。欠席者は会議の文脈を持たない。出席者は、決定事項と自分のアクションアイテムを確かめるために読む。

## 2. 節の並び

- 依頼者か宛先に議事録の雛形があるときは、節の並び・見出しの形・日時や出席者の書き場所を雛形に合わせる。雛形の有無は brief で聞く(`../process.md` 2.)。組織の議事録は決まった形で保管され、読み手はその形で決定事項と自分の担当を探す。
- 雛形が無いときは、日時・場所・出席者、議題、話題ごとの記録、決定事項、アクションアイテム、次回の順に置く。Markdown では日時・場所・出席者を frontmatter に書き(`../format/markdown.md` 2.)、本文に同じ内容の節を作らない。同じ内容を 2 か所に書くと、片方だけが直される。
- 決定事項・アクションアイテムが無い会議では、その節を作らない。話題は会議で出た順に並べる。アクションアイテムには担当と期限を書く。決定事項とアクションアイテムは並列の項目として箇条書きにしてよい(`../paragraph.md` 1.)。

## 3. 足す規則

- 議事録を推敲するときは、話題の順と見出しを変えない。散文の記録を項目に分けるのはよい。話題ごとに並べ替えるのは、会議のメモから新しく作るときに限る。
- 発言を引用するときは、`../sentence.md` 4. の「引用した話し言葉と、改行で区切る書き方は、読解を妨げない限り均さない」に従う。
- 素材に無い担当・期限は作らない。会議で確定しなかった担当と期限は「未確定」と書く。
- 書くのは、会議の中の発言・質疑応答・決定事項である。会議で使った資料に書いてある内容の説明は書かず、資料へのリンクを冒頭に書く。読み手は資料を持っており、議事録でしか得られないのは資料に無い発言である。
- 発言は「〜(名前)」の形で書く。「名前は〜と述べた」の文にすると、どの項目も名前で始まり、読み手は内容で項目を探せない。発言者を確定できない発言には名前を付けない。
- 質疑応答は発言の箇条書きに混ぜない。話題ごとに、発言の箇条書きの後へ「質問」「回答」の 2 列の表を書き、1 組を 1 行にする。箇条書きに混ぜると、どの回答がどの質問に対応するかを読み手が組み立てることになる。
- 確認が済んだ時点で削除する記述は、成果物に書かない。該当するのは、確認待ちの印・確認事項の一覧・作成方法と未確認の範囲の注記である。確認は依頼者への返答で聞く(`../process.md` 4.)。確定していない名前と数値は本文に書かず、回答を受けてから書く。議事録は出席者と欠席者に配る記録であり、作り手と依頼者の間の確認は読み手の用件ではない。

## 4. 外してよい規則

- `../paragraph.md` 3. の「結論から始める」と「『なぜ』が伝えたいことにつながらない節は、節ごと削る」は外す。記録は会議の順に並べ、議題を削らない。
- `../sentence.md` 4. の【要確認】のラベルは、依頼者に聞けるときは外す(3.)。

## 5. 検査で見る点

- `lint.py --genre business` で検査する。ファイル名に `minutes` か `議事録` を含むときは、`hooks/inspection.config.json` の doctypes が検査 hook に business を割り当てる。
- アクションアイテムのすべてに、担当と期限か「未確定」があるか。
- 話題の順が会議の順と一致するか。
