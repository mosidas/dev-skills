# 仕様書と規約

本ファイルは、仕様書・規約・運用の規則(実装と運用で守る要求を項目ごとに定める文書)の決まりを定める。

## 1. 読み手

読み手は実装者・運用者・レビュー役である。通読せず、項目を識別子で引いて読む。

## 2. 節の並び

冒頭に目的と範囲を書く。続けて、用語、要請レベルの対応(規約のとき。本体より前に置く)、本体、例外の順に置く。本体には 1 項目に 1 つの要求を書き、項目ごとに識別子を付ける。

## 3. 足す規則

規約の要請レベルを規定する場合、[RFC2119](https://www.nic.ad.jp/ja/tech/ipa/RFC2119JA.html) に対応する語句を使用し、その対応をドキュメントの最初で明示する。決まりの立場と、要請と操作の説明の書き分けは `../sentence.md` 2. に従う。

| 要請レベル | 語句 | 説明 |
| :-- | :-- | :-- |
| MUST | しなければならない、する | 絶対に守る必要がある。 |
| MUST NOT | してはならない、しない | 絶対に禁止される。 |
| SHOULD | する必要がある、推奨される、が望ましい | 原則として従うべきだが、理由があれば例外も許容する。 |
| SHOULD NOT | しないほうがよい、推奨されない、避ける | 原則として避けるべきだが、理由があれば使用を許容する。 |
| MAY | してもよい、できる | 任意で使用してよい。個人の裁量に任せる。 |

## 4. 外してよい規則

`../paragraph.md` 4. の「議論を支えない装飾的精度(時刻、HTTP ステータス、後で参照しない識別子)は省き、一般的な言い方で済ませる」は外す。要求に含まれる値・ステータス・識別子は省かずに書く。`../paragraph.md` 1. の「箇条書きを使ってよいのは、項目が同じ文法構造・同じ抽象度で本当に並んでいる場面に限る」は、要求の列挙には適用しない。

## 5. 検査で見る点

- 要請の語が、要請レベルの対応の表にある語だけか。
- 1 つの項目に要求が 1 つだけか。
