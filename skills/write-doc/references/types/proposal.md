# 企画書と PRD

本ファイルは、企画書(案を示して承認を得る文書)と PRD(製品要求仕様書)の決まりを定める。

## 1. 読み手

読み手は、案を承認する人である。案に至った背景は知らない。PRD のときは、PRD からタスクを起こして実装する build(dev-skills のスキル)が読み、planner(dev-skills のエージェント)は build を通して制約と決定事項を受け取る。

## 2. 節の並び

企画書は、背景と課題、目的、案、対象外、効果と根拠、リスクと対応、費用と期間、決めてほしいことの順に置く。PRD は specify の雛形 `../../../specify/references/prd.md` の節に従い、本ファイルに雛形を写さない。

## 3. 足す規則

- 目的と手段を分けて書く(`../paragraph.md` 2.)。
- 問題の後に解消を、リスクの後に対応を置く(`../paragraph.md` 3.)。
- 強い数字の算式と前提、競合の中立な記述は `../sentence.md` 4. に従う。
- 現状(As-Is)は現物で確かめる(`../process.md` 5.)。

## 4. 外してよい規則

`../paragraph.md` 1. の「箇条書きを使ってよいのは、項目が同じ文法構造・同じ抽象度で本当に並んでいる場面に限る」は、PRD の要求一覧には適用しない。要求一覧は雛形の形のまま書く。

## 5. 検査で見る点

- `lint.py --genre business` で検査する。
- 決めてほしいことが末尾にあるか。
