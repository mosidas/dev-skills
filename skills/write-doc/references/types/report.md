# 調査レポート

本ファイルは、調査・分析・評価レポート(調べた事実を判断の材料にまとめる文書)の決まりを定める。リサーチメモも本ファイルに従う。

## 1. 読み手

読み手は、レポートを読んで判断する人である。調査の過程は知らない。本人向けのメモは `../readers.md` 2. に従う。

## 2. 節の並び

冒頭に対象と範囲、結果と結論の要約を書く。続けて、次の順に置く。

1. 方法
2. 項目ごとの結果
3. 結論と次の行動か選択肢
4. 残る課題
5. 調査の記録(付録)

根拠が無いときと定点観測では、次の行動と選択肢を書かず結論だけを書く。

## 3. 足す規則

- `../process.md` 2. の brief に次の 2 行を加えて依頼者と 1 往復で合意する。素材は他者が加工した要約でなく加工前の一次資料・ログ・コード・実測値にする。要約から始めた調査では要約した人の解釈が結果に混ざる。読み手はその解釈の根拠をたどれない。手法と道具はその分野の専門家が同じ調査で使うものにする。合意した素材と手法は 2. の方法の節に書く。

  ```text
  - 素材: <加工前の素材(一次資料・ログ・コード・実測値)>
  - 手法と道具: <調べ方と使う道具(計測・再現の手順・コード検索)>
  ```

- 調査・分析の結びは、事実の再統合で終えず、根拠が支える範囲で次に何をすべきかを 1 段落書く。根拠がなければ再統合で止める。
- 調査の結びで提案を書くときは、「決める前にできる検証」と「決める場で選ぶ選択肢」に分ける。事実・解釈・打ち手を分け、どの文がどれに当たるかが分かるように書く。依頼に判断したいことがない定点観測では、選択肢を作らない。
  - 選択肢ごとに次の 3 つを添える。
    - 支える数字
    - 確かめること
    - 選ぶ条件(「検証で〜なら A、〜なら B」)
  - 選択肢は次の 3 つの案から作り、素材にない施策や数字(期間・費用・効果の見込み)は足さない。
    - 素材にある関係者の案
    - 検証の結果で決まる案
    - 何もしない案
- 定例・月次報告など続きの報告は、`../process.md` 5. の続きの文書の規則に従う。
- 強い数字の算式と前提は `../sentence.md` 4. に従う。
- 残る課題の節には、まだ決まっていない事項だけを載せる。方向性が決まった事項は結論の節に書くか、載せない。節を書くたびに、各項目の「現時点の案」がすでに決まった方針になっていないかを確かめる。

## 4. 外してよい規則

`../paragraph.md` 4. の「議論を支えない装飾的精度(時刻、HTTP ステータス、後で参照しない識別子)は省き、一般的な言い方で済ませる」は、付録の調査の記録には適用しない。再現に必要な日時・バージョン・コマンドは省かずに書く。

## 5. 検査で見る点

- 結論の文のそれぞれに対応する事実が項目ごとの結果にあるか。
- 出典を読み手がたどれるか(`../sentence.md` 8.)。
