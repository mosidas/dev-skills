# README

本ファイルは、リポジトリの README(リポジトリを開いた人が最初に読む文書)の決まりを定める。雛形は `../templates/readme.md` にある。

## 1. 読み手

読み手はリポジトリを初めて開いた人である。使う人と開発に参加する人の 2 種類がいる。使う人は、何をするものかと、入れて動かすまでを知りたい。開発に参加する人は、ビルドとテストの動かし方を知りたい。どちらもコードを読めるが、まだ読んでいない。README はコードを読む前に読む文書であり、コードを読めば分かることを読み手に先回りして伝える文書ではない。

## 2. 節の並び

冒頭に題名と、何をするものかの 1 文を書く。導入の節は設けない。画面を持つアプリでは、1 文の直後に画面の画像を 1 枚置いてよい。続けて、動作環境(必要なもの・権限)、インストール、使い方、開発、ライセンスの順に置く。使い方は利用者が最初にする 1 つの流れだけを書き、開発はビルドとテストのコマンドを 1 つずつ書く。該当しない節(ライブラリのインストールなど)は削る。

## 3. 足す規則

- 書くのは、コードを読んでも分からないことに限る。目的、動作環境、権限とその用途、入手と導入、既定の保存先、配布物の形式、ライセンスがこれに当たる。判定の問いは「読み手がこれを知るために開くファイルを、読み手自身が名指しできるか」である。名指しできること(ディレクトリ構成・内部の層・関数名・設定ファイルのキーの一覧・依存の宣言から分かる技術スタック)は書かない。
- サブコマンド・オプション・エラーコード・キーバインドの全部の一覧は書かない。`--help` と画面が持つ。README には、最初の 1 つの流れに出てくるものだけを書く。
- 2 つ目以降の流れと場面ごとの手順(他のアプリとの連携・移行・復元)は、`docs/<場面>.md` に手順書(`procedure.md`)として分け、README からリンク 1 行で参照する。
- CI の仕組み、テスト用データの再生成、リリースの手順は `docs/` か `CONTRIBUTING.md` に分ける。
- 分量は、画面を 2 回送らずに読める量(100 行)を目安にする。超えたら、文を削るのではなく、2. に無い節と 2 つ目以降の流れを別の文書に分ける。
- インストールの節は、配布の形(Releases・パッケージマネージャー・ソースからのビルド)ごとに 1 段落で書き、起動の確かめ方で終える。

## 4. 外してよい規則

- `../readers.md` 3. の「結論の前に導入を設け、対象・経緯や用語などの前提・扱う範囲を説明する」は外す。題名の直下の 1 文が導入に当たる。経緯は書かない。
- `../paragraph.md` 1. の「因果と経緯は地の文で書く」と「番号・記号は、後で番号を使って参照するときだけ振る」は、使い方の操作の順序には適用しない。操作の順序は番号付きの箇条書きにしてよい。

## 5. 検査で見る点

- 各文について、読み手が開くファイルを名指しできる情報が無いか。
- 一覧が、最初の流れに出てくるものだけか。
- 使い方の流れが 1 つか。
- 開発の節のコマンドが、ビルドとテストの 2 つ以内か。
- 100 行を超えていないか。超えているとき、分ける先の文書が決まっているか。
- リンク先の文書が存在するか。
