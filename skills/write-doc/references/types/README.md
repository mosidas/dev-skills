# 文書の種類

このディレクトリには、文書の種類ごとの参照ファイルが入る。各ファイルは次の 5 節を持つ。

1. 読み手: その種類の文書を読む人と、その人が知っていること・知らないこと。
2. 節の並び: 文書の冒頭から末尾までに置く節とその順序。
3. 足す規則: 共通の規範に加えて、その種類で守る規則。
4. 外してよい規則: 外す規則を `<ファイル> <節>` で名指しし、外す条件を書く。
5. 検査で見る点: 書き終えた文書で、その種類に固有に確かめる点。

技術文書の種類は Diátaxis(技術文書を 4 つの型に分ける枠組み)の 2 軸で判定する。1 つ目の軸は読み手が内容を行動に使うか理解に使うかである。2 つ目の軸は読み手が学習のために読むか作業のために読むかである。2 軸の組は次の型に当たる。

- 行動と学習: チュートリアル
- 行動と作業: ハウツー
- 理解と作業: リファレンス
- 理解と学習: 解説

| 種類 | ファイル | 扱う文書 | 主な読み手 | Diátaxis の型 |
| :-- | :-- | :-- | :-- | :-- |
| 手順書 | `procedure.md` | 手順書・マニュアル | 手順を再現する人 | ハウツー |
| 仕様書と規約 | `spec.md` | 仕様書・規約・運用の規則 | 実装者・運用者・レビュー役 | リファレンス |
| 議事録 | `minutes.md` | 議事録 | 出席者と欠席者 | 型の外(記録) |
| 調査レポート | `report.md` | 調査・分析・評価レポート、リサーチメモ | 判断する人 | 型の外(判断の材料) |
| 技術記事 | `article.md` | 技術記事・技術書の章・解説文 | 題材を知らない他者 | チュートリアルか解説の一方 |
| 企画書と PRD | `proposal.md` | 企画書・PRD(製品要求仕様書) | 承認する人。PRD は build | 型の外(承認の材料) |

議事録・調査レポート・企画書と PRD は記録と判断のための文書であり 4 つの型の外にある。

1 つの文書には 1 つの型だけを持たせる。型を混ぜた文書では読み手が目的に関係しない部分を読み分けながら進む。手順書の中で設計の経緯と代替案を論じない。チュートリアルにリファレンスの一覧表を入れない。別の型の内容はその型の文書か付録の節に分ける。文書に分けたらリンクで参照する。付録の節は本文の後に設ける。型の外の 3 種類も同じである。手順書の設定値と参照の表は付録の節に当たる。調査レポートの調査の記録も同じである。

表に無い種類は `../process.md` 2. の brief で形式を合意する。
