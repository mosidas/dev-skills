# HTML の形式の規範

## 1. 折りたたみのラベル

- HTML で配布する文書の折りたたみ(`<details>` の `<summary>`)のラベルも、見出しと同じ規則(`../paragraph.md` 6.)に従う。「〜を開く」「〜を表示」のような操作の文にせず、開いたときに現れる内容を特定する名詞句にする。
  - Before: 「候補 B の表を開く」
  - After: 「候補 B の対応表」

## 2. HTML の資料の規則

HTML で配布する説明資料(図・表・切り替えの UI を持つ 1 ページの文書)で守る規則である。資料の作り方の工程は write-page が定める。

- 同じ種類の表は、列の並びと列の幅をそろえる。表ごとに列の位置が変わると、読み手は表を見比べられない。
- 一覧は省略せず、全件を縦に並べる。「n 件」「ほか」「など」で省略しない。一覧が長いときは、折りたたみに入れてよいが、中身は全件にする。
- 切り替えの操作(タブ・メニュー)と、切り替わる表示先を隣接させる。操作と表示先が離れると、読み手は何が切り替わったかを見失う。表と図を切り替えるときは、表と図を 1 つの UI に入れる。
- 同じ種類の要素は、折りたたみの有無をそろえる。候補 A の表を開いたままにして候補 B の表だけを折りたたむ、のような不ぞろいにしない。
- すべての表は、面(本文の背景と別に持つ表の面の色)と枠線で本文の背景と区別する。面が背景と同じ色だと、行の境目が読めない。
- 折りたたみ(`<details>`)の `<summary>` のラベルは、1. に従う。
- 本文の行幅は、ページの本文の幅と同じにする。本文の幅より狭い位置で折り返さない。本文の幅そのものは、構成を合意するときに決める。
- 図は、本文の幅で横スクロールを出さない。横に長い図は、縦のスイムレーンに組み替えるか分ける(`../../../draw-diagram/references/svg.md` 1.)。
- タブ・行の分け方は、本文の節の分け方と 1 対 1 にする。本文が対象ごとに節を分けているなら、タブも対象ごとにする。
- 中間ファイルを参照しない(`../readers.md` 3.)。前版の資料と、本ページに無い図も参照しない。版を改めるときは、前版の内容を本ページに取り込む。
