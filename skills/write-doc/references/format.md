# 表記・書式の規範

## 1. 文書構成

- 見出しはレベル 2〜5 に付番する(レベル 2 は `1.`、レベル 3 は `1.1.`、以下同様)。レベル 1 とレベル 6 以上には付番しない。
- 本文は最下位の見出しの下にのみ置く。本文を持つ見出しの下にさらに見出しを置かない。
- 見出しは、その節が報告する内容を特定する名詞句にする。命題を「〜こと」で名詞化した見出し、結論を言い切るセリフ、数値を含む見出しにしない。
  - Before: 「失敗が 60 秒で起きること」「この取込だけが重いこと」
  - After: 「失敗までの経過時間の測定」「クエリごとの所要時間の比較」
- HTML で配布する文書の折りたたみ(`<details>` の `<summary>`)のラベルも、見出しと同じ規則に従う。「〜を開く」「〜を表示」のような操作の文にせず、開いたときに現れる内容を特定する名詞句にする。
  - Before: 「候補 B の表を開く」
  - After: 「候補 B の対応表」
- 推敲では、原文にある短い動作の見出し(「設定を見直す」)を名詞句に言い換えない。文書の題(レベル 1)も変えない。新しく書く見出しは、上の名詞句の規則に従う。
- 「〜とは」とコロンで話題をつないだ見出しは、コロンの後の語句を落とさずに名詞句にする。文書の種類と対象を区切るラベルのコロン(「議事録: 10 月定例会」)は残す。
  - Before: 「uv とは: インストール手順」
  - After: 「uv のインストール手順」
- 見出しから外した警告・条件・結論・範囲・順序・手段・書き手の評価は、本文になければ本文へ移して同じ意味で残す。
- 見出しの後ろに括弧で補った語句と、結びの「〜について」は外す。括弧の中の条件・期限は、本文になければ本文へ移す。節が括弧の中身だけを扱うときは、括弧の語を見出しにしてよい。管理番号・画面の項目名を示す括弧(「(REQ-118)」)は残す。
  - Before: 「デプロイの手順(本番前まで)」「ログの保存期間について」
  - After: 「デプロイの手順」「ログの保存期間」
- 一つの見出しに「と」「・」で二つの主題を並べない。主題が二つあるなら節を分ける。「A と B の照合」のように結び付き自体が主題のときに限って使う。
- 同じレベルの見出しは粒度を揃える。文書全体の構成要素を指す見出しと個別の対象を扱う見出しを同じレベルに並べない。
- 議事録を推敲するときは、話題の順と見出しを変えない。散文の記録を項目に分けるのはよい。話題ごとに並べ替えるのは、会議のメモから新しく作るときに限る。
- 作成日・版・対象コミットなどのメタ情報は frontmatter に書く。本文へ書くのは、読み手の判断に関わる場合に限る。

## 2. 表記

- Markdown 形式で記述し、GitHub での表示を前提に [GitHub Flavored Markdown](https://github.github.com/gfm/) に従う。
- 英数字は半角を使用する。
- 文体は常体で統一することを推奨する。読み手に答えを求める問いは、常体の文書でも敬体で書く(`readers.md` 3.)。
- 能動態を優先する。
- 体言止めを避ける。
- 略語は、初出時に正式名称を併記する(例: `GitHub Flavored Markdown(GFM)`)。
- 外来語(カタカナ)の表記は[外来語表記ガイドライン](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/kokugo_kadai/iinkai_45/pdf/93390601_09.pdf)、漢字・送り仮名は[公用文における漢字使用等について](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/sanko/koyobun/pdf/kunrei.pdf)、物理量の単位は[国際単位系](https://japanknowledge.com/contents/common/si.html)に従う。
- 補助動詞と、形式名詞の「事」「為」はひらがなで書く。中身のある名詞(「事の経緯」)は漢字のまま残す。
  - Before: 「実行して下さい」「指定出来る」「確認して頂く」「試して見る」「する事」「する為」
  - After: 「実行してください」「指定できる」「確認していただく」「試してみる」「すること」「するため」
- 規約の要請レベルを規定する場合、[RFC2119](https://www.nic.ad.jp/ja/tech/ipa/RFC2119JA.html) に対応する語句を使用し、その対応をドキュメントの最初で明示する。

| 要請レベル | 語句 | 説明 |
| :-- | :-- | :-- |
| MUST | しなければならない、する | 絶対に守る必要がある。 |
| MUST NOT | してはならない、しない | 絶対に禁止される。 |
| SHOULD | する必要がある、推奨される、が望ましい | 原則として従うべきだが、理由があれば例外も許容する。 |
| SHOULD NOT | しないほうがよい、推奨されない、避ける | 原則として避けるべきだが、理由があれば使用を許容する。 |
| MAY | してもよい、できる | 任意で使用してよい。個人の裁量に任せる。 |

- 必要に応じて[アラート記法](https://docs.github.com/ja/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#alerts)を使用してよい。

## 3. 記号

- 区切り符号は句点「。」・読点「、」・中点「・」・コロン「:」を使用する。
  - 句点は文の終わりに使用する。ただし、箇条書き・例の表記で名詞句のみを記述する場合は使用しない。
  - 読点は長い文の節の区切りに使用する。短い文・表のセル・箇条書きでは語句を「xx、xx」と読点で並べない。短い文では「主題は、述語」の読点も使用しない。
    - 間を作るだけの読点は外す。主語の「が」、短い目的語の「を」、主題の「は」「も」「には」「では」「とは」のすぐ後の読点、「A ではなく B」の「なく」の後の読点、並べの頭の主題(「1 つ目は、」)の後の読点、見出しの中の読点がこれに当たる。見出しは「A ではなく B」の形にせず、B だけを書く。
      - Before: 「ログが、二重に出力される」
      - After: 「ログが二重に出力される」
    - 読み分けの役目がある読点は残す。主題の後に別の動作主が続くところ(「レビューでは、担当者が差分を説明した」)、長い主語・目的語や節の後、条件・場面の枠(「〜場合は、」「〜するには、」)、長い文で並べた語のあいだ、外すと掛かり先が変わるところ、文頭の接続(「具体的には、」)、逆接・譲歩(「〜が、」「〜ても、」)、引用・コードの中がこれに当たる。
  - 名詞の並列は中点か「と」でつなぐ。
  - コロンは、用語・記号を説明する場合と、箇条書きの頭で短い値を示すラベルの場合に、その後ろに付けて使用する。
    - 箇条書きの頭のラベルとコロンは、コロンの後が値か説明の文かで分ける。日時・場所・担当・数値・状態のような短い値の項目(「状態: 対応中」)と、用語・引数・設定項目の名前に説明が続く項目は残す。分類の語(「特徴」「改善点」)、出来事を名詞にまとめた語(「応答速度の低下」)、短い述語のラベルは、ラベルとコロンを外し、ラベルの意味を説明の文に入れる。番号・項目の数・順は保つ。
      - Before: 「1. 応答速度の低下: ピーク時に 3 秒を超えた。」
      - After: 「1. 応答が遅くなり、ピーク時に 3 秒を超えた。」
- 分かち書きには半角スペース「 」を使用する。
- 引用符号は鉤括弧「」、範囲を表すときは波ダッシュ「〜」、省略は三点リーダー「…」、小数点はピリオド「.」、桁区切りはカンマ「,」を使用してよい。
- 括弧は半角の `()`・`[]`・`{}` を使用する。
- 数式・コード・固有名詞を除き、上記以外の記号は使用しない。
- 全角スペースは使用してはならない。

## 4. 出典

- 出典は URL をリンクにし、リンクテキストを資料の正式な名前(サイト名・ページ名)にする。URL をそのまま書かない。
  - Before: 「出典: [文化庁の資料](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/sanko/koyobun/pdf/kunrei.pdf)」
  - After: 「出典: [公用文における漢字使用等について](https://www.bunka.go.jp/kokugo_nihongo/sisaku/joho/joho/kijun/sanko/koyobun/pdf/kunrei.pdf)」
- 読み手がたどれない出典(「社内調査」、確認日だけの記載)は書かない。たどれない根拠しかない記述は、`sentence.md` 4. に従い事実として書かない。書籍など URL のない公刊資料は、書名・著者・出版社で示す。
