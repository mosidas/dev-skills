# 作図規範

## 1. 図を描くかどうかの判断

文や表で済むなら描かない。図は、要素どうしの関係・データの流れ・境界・状態遷移など、文では追いにくい構造を示すときだけに描く。1 図には 1 つの主張だけを持たせる。複数の主張があるときは図を分ける。説明のための図で部品(主体・コンポーネントとそれらをつなぐ辺)が 3 つ以上あるときは全部を 1 図に描かない。前の図を描き直して部品を 1 つずつ加えた図の列にする。読み手は部品が組み上がる順に仕組みを追える。列の各図の主張は新しく加えた部品の役割である。そのため列は 1 図 1 主張の規則と両立する。全部の部品を一度に描いた図は参照用の図として列の最後に加える。仕様書の構成図のような参照用の図には本規則を適用しない。スライド・報告書などの配布資料に埋め込む図も本規範で描く。`.mmd` は構造の確認に使い、配布物には 2. の工程で書いた SVG を使う。mermaid の描画をそのまま埋め込まない。

## 2. 工程

- 種類と構図を決める(`references/mermaid.md`)。
- 構造を `.mmd` に書く。ノードと辺だけを決め、配置と装飾は決めない。
- SVG を書く(`references/svg.md`)。
- `render.py` で `.mmd` と SVG の対応を照合し、禁止事項を検査する。
- `--png` で PNG にして画像として目視する。サンドボックス内では Chrome が起動できないため、サンドボックス外で実行する。目視では、括弧・矢印・三角の向きと矢尻の有無を 1 つずつ確かめる。`render.py` が見るのは、`data-id` と `data-edge` の属性の照合と、`data-edge` を持つ path・line の斜めの線分(polyline・polygon と transform は対象外)であり、ほかの図形の形は見ない。
- 埋め込む(`![図の要約](x.svg)`)。alt には図が伝える主張を書く。

`.mmd` と SVG は同じ basename で対にして残す(`references/examples/cache-read.mmd` と `cache-read.svg` が対応例)。1. の図の列では図ごとに `.mmd` と SVG を対にして残す。basename には列の順の番号を付ける(`cache-read-1`・`cache-read-2`)。`references/examples/cache-read` は列の最後の図に当たり単独では参照用である。PNG は生成物であり、リポジトリに残さず一時ディレクトリへ出す。

`render.py` の呼び方。

```
python3 <スキルのディレクトリ>/scripts/render.py <x.mmd> <x.svg> [--png OUT]
```

`<スキルのディレクトリ>` には CLI がスキル読み込み時に示す絶対パスを入れる。

## 4. 規範の要点

- 名前を書いた箱の羅列でなく、仕組み(データの流れ・境界・追加される辺)を描く。
- 主体・領域は subgraph の枠、処理・情報はノードで描き、動作主の箱と処理の箱を同じ粒度で並べない。
- フローチャートの順序は辺と判定のひし形の分岐(はい / いいえ)で示し、番号つきの矢印で示さない。
- 比較は Before/After の値の並びでなく、差分そのものを描く。
- 矢印にはラベルを付ける。何が渡る辺なのかを矢印だけで示す。
- 接続線は水平・垂直の線分と角丸の曲がりで描き、線を箱より先に描く(`references/svg.md` 9.)。斜めの線分は `render.py` が検出する。
- 説明文は図の中に書き込まず、図の外のキャプションに記載する。軸(横が時間、縦が主体など)と帯・レーンが何を表すかも、キャプションに書く。図の中の帯の題だけでは、読み手は帯の目的を取れない。
- 要素の区別は枠線の色でなく塗りで付ける。凡例は塗り・線色に意味を持たせた図にだけ付け、見本の図形と意味の文を書き、見れば分かること(色名・塗り・線種・形)を書かない。ファイル・DB は色でなく円筒の形で示す。
- 見積もった文字幅が箱を超えないようにし、PNG で目視する。

## 5. 優先規則

- `render.py` の照合(`references/mermaid.md` に定める記法の範囲)を、図の見た目より優先する。照合が通らない書き方は、通る書き方に描き直す。
- 日本語のラベル・キャプションは write-doc の規範(`../write-doc/SKILL.md` と references)に従う。
